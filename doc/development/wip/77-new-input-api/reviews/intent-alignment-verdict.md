## Top-line verdict

**Holds together — with caveats.** The landed implementation faithfully delivers the stakeholder
request on every load-bearing axis: the poll-a-reftable idiom is gone and replaced by a callback
API that is dramatically nicer at the call site; the overlay gate — the audit's central drift
finding (D-A) — is genuinely removed in code, not just in prose; `isrepeat` is restored;
the singleton, the four-tier chain, submit/cancel chains, boundary callbacks, cursor/text control,
and the mutable-API boundary all land as ratified. The prior audit's verdict ("design layer
faithful; drift localised to the contract record") **carries forward and is closed in the right
direction**: the code implements the route-centric model the sources intend, not the
widget-as-router mechanism the old contract record had mirrored.

The caveats are real but localised — none reverses the architecture: (1) the project-pollable
`compy.keys_pressed` surface promised by the spec summary and D-10 **did not land**; (2) the
migrated examples and the new user guide promote a **legacy `eval` evaluator object** to primary
API — an unrecorded deviation from the spec'd `validator`/`highlighter` surface, i.e. exactly the
"mechanism encoded as contract" failure mode the owner's framing warned against; (3) a scatter of
smaller spec/implementation gaps (`multiline` unimplemented; proxy iteration inert on LuaJIT;
config-key silent drops vs the warn-don't-swallow discipline; combo-tier repeat semantics still
unsettled at an rc tag). All are itemised in §4 and the "For the owner" list.

## §1 Are the four pains dissolved?

Owner posture held to (per `notes/stakeholder-3-input/assessment.md`, human framing 2026-06-22):
pains are symptoms of the feature's absence, to be **dissolved**, not platform behaviours to
reproduce. Verdict per pain:

**P1 — event-order inversion: DISSOLVED, correct posture.** No order gate or order guarantee
appears anywhere in the diff. The gateway (`controller.lua`, `handlers.keypressed/textinput/
keyreleased`) does bookkeeping + shortcuts and hands each channel independently to the slot
occupant; nothing gates a glyph on a keypress flag. The old `if user_input then … else
love.keypressed` overlay gate — the code-level root of the "press twice after a chord" pain — is
deleted (patch @ `controller.lua` hunk `@@ -622,34 +892,30`, the hunk the owner's own in-code
annotation marks "the CORE CHANGE OF THE DIFF AND IT LANDS AS EXPECTED"). Order was not
reproduced as a contract — the design is order-independent, which is the ruled posture.

**P2 — `isrepeat` stripped: DISSOLVED (restored).** The gateway signature is now
`function(k, sc, isr)`; `isrepeat` is threaded through the route into every chain tier —
tier-3 `on_key_pressed(k, keys_pressed, isr)`, wrapped natives, and the sink
(`UserInputController:keypressed(k, keys_pressed, isr)`). The typing-tutor fix the assessment
named ("`if isrepeat then return` deletes the whole block") is now available to project code.
Two residuals, neither a posture violation: (a) `scancode` — the other half of the assessment's
threading ask — is *not* threaded; the uniform chain signature deliberately puts `keys_pressed`
in LÖVE's scancode position (spec §2, doc A §9 "resolved"), so a native reading scancode would
silently get the proxy. No in-repo example reads scancode (`keyboard/main.lua:134` is
`love.keypressed(k)`), so this is a documented-signature question, not a break. (b) The
**combo-tier** repeat question P2 raised is still open — see §4 item 6.

**P3 — modifier chords emit no textinput: DISSOLVED via the sanctioned path.** Combo dispatch
landed exactly as the assessment sanctioned: `compy.input.handlers.keypressed['ctrl+s'] = fn`
(per-event normalising tables, `util/key.lua new_handler_table`; canonical serialisation
`combo_string` with ctrl<alt<shift<gui precedence, l/r folded). The chord boilerplate the
keyboard example hand-rolls collapses into a one-line registration. No attempt anywhere to
"fix" the platform behaviour itself — correct, per the quirks doc's own "none needed".

**P4 — no exit cleanup: correctly PARKED, with the in-scope half delivered.** The T3
global-state snapshot/restore is not in the diff — per the owner ruling it is a sibling
concern (A1), outside #77's widget scope; the diff does not smuggle it in. The
project-internal-teardown half, `compy.before_exit`, **did** land (consoleController.lua:
namespace slot + `stop_project_run` invokes it before teardown) — with clean provenance
(M6-02, human-approved session 23; `design/roadmap.md:266`, `design/spec/M5c-dispatch-chain.md:141`).
Scope discipline held.

**The umbrella pain — the poll idiom & the three tier-1 frictions:** the reftable/`is_empty()`
poll is removed with the legacy globals (`user_input`/`input_text`/`input_code`/
`validated_input`/`write_to_input` all deleted from `prepare_project_env`; no shim — an
ordinary nil call, exactly the D-1 consensus). "Inconsistent with the rest of LÖVE" →
callback-driven like the rest of LÖVE. "Parallel keyboard handling is a PITA" → tiers 2–3 fire
whether or not the widget is shown (FR-6; the gate that caused the lockout is gone). "Not easy
to hide/show" → `show()`/`hide()` one-liners on a boot-provisioned singleton (NFR-1,
`src/main.lua` ui_m/ui_c/ui_v constructed once at load). One qualification: the *pollable
held-key set* half of the dissolution story did not land — §4 item 1.

NFR-4 proven by the examples (§3) ✓.

**Exceptions (spec letter not honored):**
- **`compy.keys_pressed` (spec.md summary; D-10 "stays global"; the owner's own proto-design
  sketch) is not exposed to projects.** `Controller.keys_pressed` exists framework-side and the
  read-only proxy rides every chain signature, but no `compy.keys_pressed` (nor any equivalent)
  is in the project namespace (`get_compy_namespace`: terminal/audio/graphics/fonts/input only).
  A project can read held keys **only inside a callback** — it cannot poll them in `update()`.
  See §4 item 1.
- **`multiline` (spec §3, "Shift+Enter newlines, default false") is unimplemented.** No config
  key, no flag; Shift+Enter newline is unconditionally available (pre-existing sink behaviour).
  Spec §12 claims "this file adds none of its own [deviations]" — this one is unrecorded.
- **Proxy iteration (spec §1 "pairs-iterable") is inert on the shipping platform.** The
  implementation's own comment (controller.lua `held_keys`) concedes `pairs(proxy)` yields
  nothing under LuaJIT/5.1 (`__pairs` is 5.2+); read-indexing + write-raise hold (and are
  tested). The tier-2 stakeholder asked for indexing *in addition to* iteration, not instead.
- **R4's "channel caveats marked in code at the dispatch site"** (Ctrl-chords emit no
  textinput, etc.): no such marker exists at the dispatch site (grep over
  `projectInputController.lua`/`controller.lua`/`userInputModel.lua` — nothing). Doc-hygiene
  letter of a ratified ruling, unfulfilled.
- **§8's design-claim "an uncitable deviation is forbidden" is violated by the shipped API
  surface**: the `eval` and `result` config keys exist in `apply_config` and `eval` is
  documented as primary API in `doc/input_api.md` — neither appears in spec §3's config table
  nor in §9/§12's deviation registers. See §4 item 2.

## §3 Do the example migrations prove the ergonomics?

**Yes — the before/after is the strongest intent evidence in the diff.** Every migrated example
is shorter, event-driven, and free of the update-loop input machinery:

- **repl** (`src/examples/repl/main.lua`): 9 lines of poll loop → 8 lines total, zero polling;
  this is the R1 soft target ("soliciting input with nothing but `show{…callbacks…}`") proven
  verbatim, and the user guide's quick start.
- **guess / valid**: the `love.update` poll-plus-rearm dance collapses into
  `show{prompt, eval, on_text_entered}` + a one-line `after_submit` re-show — the spec §5
  continuous-session idiom exactly as written.
- **tixy** (the owner's named showcase): `write_to_input(body)` → `compy.input.set_text(body)`;
  the poll in `love.update` is gone; the after_submit re-show re-injects the submitted body so
  the user keeps editing in place — a *better* interaction than the legacy one, not a port.
- **turtle**: `input_text("TURTLE")` + poll → a 4-line `show{}` inside its (retained, R7-wrapped)
  native `love.keyreleased` — native coexistence working as ruled.
- **balloons** (nested `56347d0`): `terminal_read` per-frame poll deleted; delivery is
  push-based via `on_text_entered`; the changing prompt uses `configure{prompt}` live — the M7
  surface earning its keep.

**Friction found — and it is informative, not cosmetic:**
- **maze** (nested working-tree patch) is the one migration that could *not* go fully
  event-driven: an invalid submit's re-show with preserved text must be **deferred a tick**
  (`need_reopen`/`reopen_text` + `rearm_input` on the update loop), and the shown-guard reads
  **`love.state.user_input` directly** — a framework-internal mechanism flag, because the public
  API has **no "is the widget shown?" query**. Part of the deferral is game logic (wait out the
  player animation), but the internals read is a plain API gap: the first non-trivial consumer
  needed a visibility predicate and had to reach under the API to get it. A residual per-tick
  re-arm poll — the very shape the feature dissolves — survives in the flagship migration.
- **The examples don't use the spec'd validation surface.** guess/valid/tixy pass
  `eval = ValidatedTextEval({…})` / `InputEvalLua` — the legacy evaluator objects — instead of
  spec §9's mapped `validator = fn`; `doc/input_api.md` then canonises `eval` as the documented
  config key with `validator` demoted to "lighter-weight alternative". The ergonomics are fine;
  the drift is contractual (§4 item 2).
- **The continuous-session idiom carries a documented footgun**: `after_submit` (and the whole
  field-write-only family) passed inside `show{}` is **silently dropped** — the user guide
  itself warns "no error, no warning, your callback just never fires and the widget never
  reopens". For the headline idiom of the API, the failure mode of the obvious wrong guess is
  silence — against the C2 / warn-on-suppression discipline the spec claims everywhere else
  (spec §11 row 11).
- **keyboard** (the tier-3 pains showcase) was deliberately untouched (pure-native, keeps
  working — verified excluded in the manifest). Legitimate under R7, but it means the
  "INPUT.shift/ctrl/alt bookkeeping collapses into keys_pressed + combos" dissolution story is
  demonstrated by no example; and **maze kept its hand-rolled key-state half**
  (`tab_was_down` edge-tracking, `is_shift_down()` via `love.keyboard.isDown`,
  `maze/main.lua:509–564`) — consistent with there being no pollable `keys_pressed` for it to
  migrate onto (§4 item 1).

## §4 Drift / controversy / gap — named, cited, classified

1. **`compy.keys_pressed` never exposed to projects — REAL GAP (spec + intent).**
   Promised: spec.md summary bullet ("**`compy.keys_pressed`** — live held-key set");
   `design/notes/decisions-record.md` D-10 ("`compy.keys_pressed` stays global"); the owner's
   own proto-design sketch (`decisions.md` ~261: `compy.keys_pressed = {}` updated on every
   event). Landed: framework-internal `Controller.keys_pressed` + callback-argument proxy only;
   nothing in the project namespace. Consequence: held-key polling (movement keys in `update()`,
   maze's exact case) still requires `love.keyboard.isDown` + hand-rolled edge state — the
   tier-3 "keys_pressed replacement case" remains undissolved. Needs an owner ruling: expose it
   (small, additive) or amend spec/D-10 to the callback-argument-only contract.
2. **Legacy evaluator objects (`eval`, `result`) leaked into the public API — REAL DRIFT,
   unrecorded deviation.** `apply_config` accepts `eval`/`result`; examples use `eval=`;
   `doc/input_api.md` documents `eval` as a first-class config key (with `InputEvalText`/
   `InputEvalLua`/`ValidatedTextEval` as sanctioned globals) while spec §3 has no such key and
   §9/§12 record no such deviation ("Nothing else … departs"). This is today's mechanism
   surfacing as contract — the precise failure mode the owner's symptoms-not-requirements
   framing (and the audit) warned about. Needs a ruling: bless `eval` (record it as a deviation,
   spec it) or realign examples + user doc onto `validator`/`highlighter`.
3. **`multiline` config flag unimplemented — GAP vs spec §3.** Behaviour is unconditionally
   multiline (Shift+Enter newline always active). Either implement or strike from spec §3;
   currently the spec promises a knob that does not exist, unrecorded in §12.
4. **`keys_pressed` proxy not iterable on LuaJIT — GAP vs spec §1**, self-admitted in code
   (controller.lua `held_keys` comment), untested (only index/write-raise are asserted),
   unrecorded in spec. The round-2 stakeholder ruling *widened* iterator-only to also allow
   indexing; the landed result *narrowed* it to indexing-only on the actual platform.
5. **Silent drop of field-write-only callbacks passed to `show{}` — CONTROVERSY vs C2.**
   Spec §11 row 11 claims warn-on-suppression "everywhere a call is refused"; the user guide
   documents this exact case as a silent footgun. One `Log.warn` on unknown config keys would
   close it. Needs a ruling only on whether the current silence is acceptable.
6. **Combo-tier repeat semantics still unsettled at an rc tag — the one genuinely-open design
   question (audit D-C / assessment item 1) shipped open.** The spec said "settle at
   implementation"; the code carries the DEFERRED marker (`projectInputController.lua:215–219`)
   and its current behaviour is **fire-on-every-repeat at tiers 1–2** (no `isr` check in
   `_dispatch`) — the opposite of the recorded provisional leaning (fresh-only at handler
   tiers). A held `ctrl+s` re-fires its handler every repeat today. Needs the owner's call —
   it was never made.
7. **No public widget-visibility query — GAP surfaced by maze**, which reads
   `love.state.user_input` (mechanism, non-binding vocabulary) from project code and keeps a
   per-tick re-arm poll. An `is_active()`-shaped read (or an `after_cancel`-driven idiom good
   enough for maze's case) is the missing piece; as long as an example ships reading framework
   internals, the "wrappers are the ONLY project-facing surface" contract
   (consoleController.lua's own comment) is contradicted by the repo's own example.
8. **`doc/input_api.md` misstates the submit lifecycle — DOC BUG (doc is "human-approved NOT
   YET").** It orders validation *before* `before_submit` and types it `before_submit(text)`;
   both spec §5 and the code run `before_submit(keys_pressed)` first, then the validator gate.
   Also: `before_submit` fires even on an empty-input Enter (code), which no doc mentions.
   Fix at the doc-approval pass.
9. **Harmless deviations, note-and-move-on:** (a) scancode not threaded; `keys_pressed`
   occupies LÖVE's scancode arg position for wrapped natives — deliberate (spec §2) but worth
   one line in the user doc for authors porting LÖVE code; (b) R4 in-code channel-caveat
   markers absent (§2); (c) `force=true` applies only the `text` subset — spec's "reconfigures
   in-place (content replaced iff text given)" is arguably satisfied, but sticky-callback merge
   happens at the wrapper regardless of `force`, a nuance the spec doesn't state; (d) minted
   mechanism vocabulary in code (`occupy_keyboard`, `forward_*`) sits at the edge of the closed
   glossary — "occupancy" is glossary-listed as non-binding mechanism shorthand, but the
   owner's own in-code annotations (45 committed `REVIEW:` remarks, e.g. controller.lua:191–193)
   already contest the naming; those annotations are themselves open owner questions shipped
   inside the landed code and should be swept to closure.

## For the owner

Rulings / decisions needed (none reverses the architecture; §4 has the full citations):

1. **`compy.keys_pressed`:** expose the read-only held-key proxy to projects as promised
   (spec summary, D-10, your own proto-design) — or amend the contract to
   callback-argument-only and accept that held-key polling stays on `love.keyboard.isDown`.
2. **The `eval` config key:** bless the legacy evaluator objects (`InputEvalText`/`InputEvalLua`/
   `ValidatedTextEval`) as public API and record the deviation — or realign the examples and
   `doc/input_api.md` onto the spec'd `validator`/`highlighter` surface.
3. **Combo-tier key-repeat semantics:** the deferred question shipped unsettled; current
   behaviour is fire-on-every-repeat at tiers 1–2, contra the recorded provisional leaning.
   This was explicitly reserved for your ruling — it is still owed.
4. **`multiline`:** implement the spec §3 flag or strike it from the spec (today: always-on
   Shift+Enter newlines).
5. **Silent config-key drops in `show{}`** (the documented `after_submit` footgun): accept, or
   mandate a warn per C2.
6. **Proxy iteration on LuaJIT:** accept indexing-only as the platform contract (amend spec §1)
   or require an iteration path (e.g. a snapshot/`each` helper).
7. **Widget-visibility query:** sanction a public `is_active()`-shaped read (maze currently
   reads `love.state.user_input` internals and keeps a per-tick re-arm poll).
8. **Sweep the 45 committed in-code `REVIEW:` annotations** (your own questions — naming,
   structure, the pointer-routing "why") to answers or removal before release; and approve/fix
   `doc/input_api.md` (lifecycle order + `before_submit` arg are wrong; doc is marked
   human-approved NOT YET).
