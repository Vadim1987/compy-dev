## ADDENDUM — the landed contract suite carries a discarded invariant (STOP, human-prompted)

The suite `tests/input/input_contracts_spec.lua` was **not** re-reviewed against the E29 re-derivation.
E29 re-derived `design.md`/`spec.md`/roadmap but left the suite as the **M4 milestone** shaped it
(`c6b5b30`, built to the *mutated* spec) — plus ~10 unaddressed human `-- REVIEW:` comments still in
the file.

**The stale green invariant.** `it('a native handler coexists with the sink')` (lines 742–758) is a
**green** M4-era row that asserts **the widget suppresses the native handler while shown**
(`assert.equal(1, native)` after `F.show_widget()`; prose: "keys go to the sink **instead**",
"auto-provisions the **lifecycle-split wrapper**"). This is the day-one replace/suppress mutation E29
**reversed**. Ratified **AC-31** requires the opposite — natives see events **even while the widget is
shown**, falling through to the sink (`native` should reach 2). The `native_split` wrapper it exercises
is precisely what **M5c scope item 6 deletes**. Human flagged this row inline (line 740). Not marked
stale; its comment actively defends the wrong behaviour.

**Aggravators.** (1) It contradicts the *other* green M4 row `it('project keys reach the project sink')`
(line 699), which asserts the project handler **does** fire while shown — opposite models, both green.
(2) The other M4-landed green Bucket-B rows (720 `stop names the console`, 768 `keypressed triple`)
were likewise never re-checked against the re-derivation.

**Why Gate 3 doesn't catch it.** M5c's only suite commitment is **AC-35** — convert the *pending*
m5/m5a/m5b/m6 rows to green. It is silent on **re-deriving the M4-landed *green* Bucket-B rows**, where
the stale invariant lives. As written, an implementer could preserve row 742 green → it then **fails**
under the correct implementation → pressure to re-enshrine the mutation.

**Recommended fix (before freezing M5c at Gate 3 — the slice is still editable until the stamp):**
1. Add an M5c scope line + AC: *the M4-landed green Bucket-B rows (742/699/720/768) are re-derived
   from AC-31/AC-1/AC-8/AC-29; specifically the native-coexist **suppress-while-shown assertion flips**
   (native sees events while the widget is shown, falls through to the sink).*
2. Mark row 742 (and its stale prose) as expected-to-flip **now**, so the intent is on record before
   implementation — not discovered as a red test mid-slice.
3. Fold the suite's ~10 inline `-- REVIEW:` comments into the M5c reconciliation (mandate guardrail 4
   already makes them design inputs — make that explicit for this file).

This keeps the *design* (AC-31) authoritative and corrects the *test* to match it — the human's
