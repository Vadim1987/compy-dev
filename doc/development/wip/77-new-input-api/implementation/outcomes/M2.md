## Surfaced gaps

### G-1 — Dead nil assignment: `compy_namespace.text_input = input_text`

**File:** `src/controller/consoleController.lua` L634  
**Finding:** This line assigns the bare identifier `input_text` to
`compy_namespace.text_input`. No local or global named `input_text`
exists at that point; the assignment silently sets the field to `nil`.
The field is never read by any other code — grep finds no consumer of
`compy.text_input` or `compy_namespace.text_input`.  
**Origin:** Pre-existing; M2 did not introduce it.  
**Risk:** None at present — it's a dead write. It may have been
intended as an alias for `project_env.input_text` (the legacy function)
but was mistyped. If `compy.text_input` is ever documented or depended
on, the assignment would silently return nil, which would surface as a
nil-call error at the call site.  
**Action:** None needed for M2. Worth removing in M8 when the legacy
`input_text` function is deleted anyway (the line becomes even more
clearly dead at that point).

### G-2 — `UserInputView` stores a `oneshot` snapshot that is never read

**File:** `src/view/input/userInputView.lua` L19, L28  
**Finding:** The view constructor snapshots `oneshot = ctrl.model.oneshot`
into `self.oneshot`, and the class annotation declares `@field oneshot boolean`.
However, `self.oneshot` is **never read** inside the view — the only
access to oneshot state is at `draw()` (L289) via the live call
`self.controller:is_oneshot()`, which reads `model.oneshot` directly.
The snapshot field is vestigial.  
**Origin:** Pre-existing; M2 did not introduce it.  
**Risk:** No functional impact today. M6 removes `model.oneshot` and
`UserInputController:is_oneshot()`; at that point the snapshot also
becomes dead, but since it was already unread it causes no breakage.
The annotation (`@field oneshot`) will become stale — minor doc debt.  
**Action:** None needed for M2 or M6. A clean-up pass (drop the field
and its annotation) can accompany the M6 `oneshot` removal.

### G-3 — `love.state.user_input` shape narrowed from `{M, C, V}` to `{C}`

**Finding:** The previous `input()` closure set
`love.state.user_input = { M = ui_model, C = ui_con, V = view }`.
M2's `show()` sets `love.state.user_input = { C = self }`. The `M`
and `V` fields are dropped.  
**Verified safe:** A grep over the full `src/` tree finds no code
outside of `consoleController.lua`'s now-removed closure that reads
`.M` or `.V`. All live consumers read only `.C` (controller.lua
L644, L653, L668, L682, L703, L719, L743, L760, L777).  
**Action:** None. Noted here so that any future code added to the
codebase knows the structure is `{C = controller}`, not the old
three-field form.
