## What will surprise the architect (surprise-first)

1. **`after_submit` is a field-write, not a `show{}` key — confirmed and
   now applied to all four examples.** `INPUT_CALLBACKS`
   (`consoleController.lua:357-369`) makes `before_submit`/`after_submit`/
   `before_cancel`/`after_cancel` field-write-assignable on `compy.input`,
   but `OUTPUT_KEYS` (`consoleController.lua:403-408`) — the only keys
   `show{}`/`configure{}` merge/stick — is exactly
   `on_text_entered`/`on_limit_reached`/`validator`/`highlighter`.
   `merge_output_keys` (`consoleController.lua:420-426`) only touches
   `OUTPUT_KEYS`, so `show{ after_submit = fn }` is silently dropped (no
   error, no warn — a genuine footgun). All four migrated examples use
   `compy.input.after_submit = function() compy.input.show{} end` as a
   standalone statement, and `on_text_entered`/`eval` as `show{}` keys.
   This corrects the illustrative recipe in `M8-chunk-plan.md` and in
   `prompts/M8-01-in-repo-migrations.md`'s own "migration recipe" section
   — those docs should be corrected for the next chunk (M8-02/M8-03) so
   nobody re-trips this. Not a design gap (the mechanism exists, the
   recipe just named the wrong delivery) — does not trigger a STOP.

2. **`eval` is neither in `OUTPUT_KEYS` nor `INPUT_CALLBACKS` — it is not
   sticky by any explicit merge step, yet it stays effectively sticky
   in practice** because `love.state.user_input_controller` (and its
   `.model`) is a single persistent singleton constructed once at
   `main.lua:371` (`UserInputModel(baseconf, InputEvalText)`) and never
   rebuilt on hide/show. `hide()` (`userInputController.lua:301-303`)
   only nils `love.state.user_input` (the draw-loop flag/handle); it
   never touches `self.model.evaluator`. `apply_config`
   (`userInputController.lua:211-214`) only calls `self.model:set_eval`
   `if cfg.eval` is truthy — a bare re-show passes no `eval`, so the
   evaluator set on the previous `show{ eval = ... }` is simply never
   overwritten and survives. Verified this by static trace (cited
   above) — **tixy's bare `after_submit` re-show
   (`compy.input.show{ text = string.lines(body) }`, no `eval` key) does
   NOT need `eval = InputEvalLua` re-passed; it was already correct as
   left on disk.** I did not add a redundant re-pass — doing so would
   have been harmless but was unnecessary once the persistence chain
   was traced. Left as originally found (verify-only, no edit needed
   here). Same reasoning applies to guess/valid's `ValidatedTextEval(...)`
   staying in effect across their bare re-shows.

3. **guess/valid validator wiring: `eval = ValidatedTextEval(filters)`,
   not a `validator =` function.** Legacy `validated_input(filters,
   prompt)` = `input(ValidatedTextEval(filters), prompt)`
   (`consoleController.lua:868-870`). `ValidatedTextEval`
   (`evaluator.lua:163-166`) builds `Evaluator.plain('plain',
   Filters.validators_only(filter))` — the exact legacy filter→evaluator
   path. Passing `eval = ValidatedTextEval({...})` in `show{}` reuses
   that path verbatim (least new logic, per the commission's own
   preference), rather than hand-rolling a `validator` function that
   re-implements filter iteration. Chosen for both guess and valid.

4. **lua-lsp flags `WARNING duplicate-set-field` on `compy.input.after_submit`
   in tixy and repl (not guess/valid)** — each file assigns
   `after_submit` exactly once; grep confirms no in-file duplication.
   This reads as a workspace-level type-inference artifact: the
   language server has no way to model `compy.input`'s metatable-driven
   `__newindex` proxy (`build_input_surface`,
   `consoleController.lua:378-396`), so it appears to merge field
   assignments to the same field name across files that declare
   `compy.input` the same (untyped) way, and flags perceived
   re-declaration inconsistently depending on analysis order/caching.
   Confirmed harmless (no real duplication, no runtime issue) — flagged
   here as diagnostic noise, not fixed (report-don't-fix; fixing would
   mean adding type annotations to `consoleController.lua`, out of this
   chunk's scope-fence).

## Per-example before/after

**tixy** (`src/examples/tixy/main.lua`, disk-survived, verified not
re-done):
- Before: `r = user_input()`; `love.update` polled `r:is_empty()` each
  frame, calling `input_code(...)` (prompt + Lua highlight) when empty,
  else consuming `r()` into `body`/`setupTixy()`/`legend`.
- After: `write_to_input(body)` → `compy.input.set_text(body)` inside
  `load_example`. Initial `compy.input.show{ prompt = "function tixy(t, i,
  x, y)", text = string.lines(body), eval = InputEvalLua, on_text_entered
  = submit_body }` at file tail (after `advance()`). `submit_body`
  (local fn) does what the old `else` branch did. Field-write
  `compy.input.after_submit = function() compy.input.show{ text =
  string.lines(body) } end` re-arms in place (continuing the just-
  submitted body, not clear-and-reprompt). `love.update` now only
  `time = time + dt` — **no polling loop remains**.

**repl** (`src/examples/repl/main.lua`):
- Before: `r = user_input()`; `love.update` polled, calling
  `input_text()` (bare prompt, default `InputEvalText`) when empty, else
  `print(r())`.
- After: `compy.input.after_submit = function() compy.input.show{} end`;
  `compy.input.show{ on_text_entered = function(text) print(text) end }`.
  No `love.update` left at all (its body was 100% the poll — dropped
  per the commission's own note). No `eval` override needed: default
  construction-time eval is `InputEvalText` (`main.lua:371`), matching
  legacy `input_text()`'s bare-text behaviour exactly.

**guess** (`src/examples/guess/main.lua`):
- Before: `r = user_input()`; `love.update` polled, calling
  `validated_input({ is_natural }, "Guess a number:")` when empty, else
  `check(tonumber(r()))`.
- After: `compy.input.after_submit = function() compy.input.show{} end`;
  `compy.input.show{ prompt = "Guess a number:", eval =
  ValidatedTextEval({ is_natural }), on_text_entered = function(t)
  check(tonumber(t)) end }`, called after `init()`. The duplicate
  `is_natural` (L11 legacy-numbered / now L11 and L25 post-edit) is
  **pre-existing shadowing — not touched**; the second definition (the
  effective one, doing digit-forall validation) is what the global
  `is_natural` resolves to at the point `ValidatedTextEval({is_natural})`
  captures it, so the wiring is faithful to legacy behaviour without any
  refactor.

**valid** (`src/examples/valid/main.lua`):
- Before: `r = user_input()`; `love.update` polled, calling
  `validated_input({ min_length(2), is_lower })` (no prompt) when empty,
  else `print(r())`.
- After: `compy.input.after_submit = function() compy.input.show{} end`;
  `compy.input.show{ eval = ValidatedTextEval({ min_length(2), is_lower
  }), on_text_entered = function(t) print(t) end }` (no `prompt`,
  matching the legacy call's lack of one). `love.update` fully removed
  (its body was 100% the poll).
