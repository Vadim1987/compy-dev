## What will surprise the architect (surprise-first)

1. **The headline risk resolved clean — proven, not assumed.** The
   commission's central question was whether a prompt set via
   `compy.input.configure{prompt=…}` **inside** `on_text_entered`
   (session still active — `submit()` calls `deliver()`, which fires
   `on_text_entered`, **before** `self:hide()`,
   `userInputController.lua:380-389`) survives the `after_submit`
   bare `show({})` re-arm. Traced statically first
   (`UserInputController:configure` → `apply_config` →
   `self.model.custom_label = cfg.prompt`, an unconditional write on
   the persistent singleton model; `hide()` never touches
   `custom_label`; a bare `show({})`'s `apply_config` only overwrites
   `custom_label` `if cfg.prompt ~= nil`, which is false for a bare
   re-show), then **proved with a new red→green contract row** (see
   below) rather than trusted on inspection alone. **Outcome: clean —
   the configured-while-active prompt survives the hide→reshow
   intact.** No design gap, no STOP. This is exactly the "plausible
   clean outcome" the commission and the M7-02 ledger both flagged as
   needing proof, not assumption — now proven.
2. **The terminal shim's public shape stayed byte-identical at the
   call site** (`ui_draw_hint()` still calls `ui.terminal.write(hint)`
   verbatim) even though the body underneath swapped from
   `input_text(msg, nil)` to `compy.input.configure({prompt=msg})` —
   the commission's own prediction ("the shim's read/write public
   shape can stay") held exactly, no ripple into `ui.lua`'s hint
   machinery beyond deleting the now-dead `read` alias.
3. **A closure-capture ordering wrinkle, resolved with a module-level
   setter (as the commission anticipated).** `ui.lua` builds
   `ui.terminal = terminal_init()` at **require time** — before
   `main.lua`'s `game_init()` (and therefore
   `game_state_router(on_input)`, the real dispatcher) exists.
   `terminal_init()` activates the session immediately (`on_text_entered
   = deliver`), so `deliver` has to close over a **module slot**
   populated later. Used the commission's own suggested shape:
   `terminal_set_handler(handler)`, called from `game_init()` right
   after `input_handler` is built (`main.lua:96`). Before that call,
   `current_handler` defaults to `noop` — inert only because no submit
   can occur before `game_init()` finishes (synchronous, same frame,
   before any `love.update` tick).
4. **A pre-existing, uncommitted diff already sat in the nested
   checkout at commissioning time** — `main.lua`'s trailing
   `-- test`/`print("ok")` comment cruft (lines 108-140 post-edit) was
   **not added by this session**; `git -C src/examples/balloons diff`
   shows it as part of the diff against the last commit only because
   it was already dirty on disk before I touched the file (matches the
   commission's own forewarning to leave it alone). Confirmed
   untouched — not part of my edit, not cleaned up, per report-don't-
   fix and the "it's the human's upstream repo" scope note.

## Before/after of the terminal shim

**Before** (`terminal.lua`): `terminal_init()` set the module global
`terminal = user_input()` (the legacy reftable) and returned
`{write=terminal_write, read=terminal_read}`. `terminal_write(msg)` =
`input_text(msg, nil)` (re-arms the whole widget, prompt = `msg`).
`terminal_read(callback)` polled `terminal:is_empty()` every frame
(driven by `main.lua`'s `hooks.update` → `ui_read_input(input_handler)`,
`ui_read_input` being a bare alias for `terminal_read`) and called
`callback(msg)` on a filled reftable.

**After**: `terminal_init()` activates the `compy.input` singleton
**once** — `compy.input.show{on_text_entered=deliver}` — and installs
a standalone field-write `compy.input.after_submit = function()
compy.input.show({}) end` (the corrected M8-01 recipe: `after_submit`
is a field-write, not a `show{}` key — `show{after_submit=fn}` is
silently dropped, per `OUTPUT_KEYS`/`INPUT_CALLBACKS` in
`consoleController.lua:357-408`). `deliver(text)` forwards to a module-
level `current_handler` slot, populated by the new
`terminal_set_handler(handler)` (called once from `game_init()`).
`terminal_write(msg)` is now `compy.input.configure({prompt=msg})` — a
**live reconfigure** of the active session (M7-02 surface), not a
re-show; no widget deactivation happens on a hint change. The
per-frame poll is gone: `hooks.update` no longer calls
`ui_read_input`/`terminal_read`, and both are deleted (dead code — zero
remaining callers, confirmed by grep across the whole balloons tree,
not just the top-level `.lua` files).

## The contract row (red → green)

Added one new row to `tests/input/input_contracts_spec.lua`, inside
the existing `describe('continuous-session idiom #m8', ...)` block
(the M8-01-landed pair already pins activate-once +
field-write-`after_submit`; this row pins the one ordering neither
that pair nor the `#m7` `configure` rows cover — configuring
**while active, from inside `on_text_entered`**, then observing the
value on the **next** session after an `after_submit` bare re-show):

```lua
it('a prompt configured inside on_text_entered ' ..
  'survives the after_submit re-show', function()
  local input = F.activate_project()
  input.after_submit = function() input.show({}) end
  input.show({
    prompt = 'first',
    on_text_entered = function()
      input.configure({ prompt = 'live' })
    end,
  })
  F.session.type('a')
  F.session.press('return')
  assert.equal('live', F.singleton.model:get_label())
  assert.is_not_nil(love.state.user_input)
end)
```

**Red→green evidence:** flipped the expected value to `'first'`
(the show()-time prompt) and reran filtered
(`busted tests --filter="prompt configured inside"`) — genuine
failure: `Passed in: (string) 'live' / Expected: (string) 'first'`,
proving the assertion discriminates the real behavior rather than
being vacuously true. Reverted to `'live'` (the correct, intended
assertion) and reran — green. This is verification of already-landed
M7-02 machinery (no production code changed for this row), not a
red-then-fixed cycle — consistent with the commission's framing ("if
the ordering isn't already covered... add one red row" to *prove* the

## Tech debt discovered (report-don't-fix — NOT fixed)

- **`terminal_write`'s unused `flushed` parameter** — carried over
  unchanged from the original signature
  (`function terminal_write(msg, flushed)`); no caller has ever passed
  a second argument (confirmed by grep — the only call site is
  `ui.terminal.write(hint)`, one argument). Kept for interface parity
  with the pre-existing public shape rather than trimmed, per the
  commission's own note that the shim's shape can stay unchanged; flags
  as a lua-lsp `unused-local` HINT, harmless.
- **lua-lsp `duplicate-set-field` on `compy.input.after_submit`**
  (`terminal.lua:24`) — the exact same known cross-file
  type-inference artifact already flagged in the M8-01 ledger (surprise
  #4): the language server cannot model `compy.input`'s
  metatable-driven `__newindex` proxy and appears to flag a
  perceived re-declaration across files that all assign
  `after_submit` the same way. Confirmed harmless (single assignment
  in this file, `grep` backstop), not fixed — same disposition as
  M8-01.
- **lua-lsp `redundant-parameter` on `current_handler(text)`**
  (`terminal.lua:10`) — a static-inference false positive: `lua-lsp`
  types `current_handler` from its *initial* assignment
  (`local current_handler = noop`, 0 arity) and does not re-infer the
  type after `terminal_set_handler` later reassigns it to a
  variable-arity closure (`game_state_router`'s returned
  `function(...) ... end`). At runtime this is inert — Lua silently
  discards extra arguments to any function call, and by the time
  `deliver` is ever actually invoked (post-submit), `current_handler`
  has already been reassigned by `game_init()`. Not fixed — a fix
  would mean adding type annotations to a nested-checkout example,
  out of scope.
- `main.lua:49`'s pre-existing `ui_set_hint(fmt(GAME_PROMPT, txt),
  true)` passes a second argument `ui_set_hint` (1-param function)
  has never accepted — a pre-existing dead argument, untouched by this
  session (not on a line I edited), flagged only because it showed up
  in the same lua-lsp diagnostics sweep as everything I did touch.
- balloons' `main.lua` trailing test-comment cruft (`-- test`/
  `print("ok")` noise, now lines ~108-140) — pre-existing per the
  commission's own note (see surprise #4); left alone.
