## Finding 1 — editor keypressed EXCLUSIVE has no regression test (spec-completeness, non-blocking to merge but must close before M4)

`tests/input/input_contracts_spec.lua:87-93`:

```lua
it('editor mode routes keys to the editor', function()
  love.state.app_state = 'editor'
  F.cc.editor:open('t.lua', '', function() return true end)
  F.session.type('q')
  assert.same({ 'q' }, F.cc.editor.input:get_text())
  assert.is_true(F.console:is_empty())
end)
```

`F.session.type` fires `textinput`, not `keypressed` (`tests/helpers/input_session.lua:16`:
`type = function(t) h.textinput(t) end` vs. `press = function(k) h.keypressed(k, '', false) end`). So
this test — despite its title — duplicates editor **textinput** coverage (already proven by the
console/project textinput pair at `:105,111`) and asserts **nothing** about editor **keypressed**
routing.

This matters because `ConsoleController:keypressed` really does branch on editor mode
(`src/controller/consoleController.lua:1033-1034`: `if love.state.app_state == 'editor' then
self.editor:keypressed(k) ... `), exactly parallel to the console's own `backspace` test at `:80-85`.
A keypressed-in-editor sibling (e.g. type text via `F.session.type`, then `F.session.press('backspace')`
and assert `F.cc.editor.input:get_text()` shrank while `F.console` stayed empty) is both meaningful and
currently absent — nothing in this suite would catch a regression that broke keypressed delivery to the
editor route specifically, while console/project stayed fine.

The comment block just above (`:71-77`) claims "the sibling rows below prove the SAME rule across the
**three real routes**" for §3.1-3.3 jointly, and the outcome ledger repeats the claim ("across console
… project-running … and editor …, §3.1-3.3"). Both overstate what the suite actually proves for
keypressed. The M4-0-03 spec calls Bucket A "**fully enumerated now** (the safety net for M4 cannot be
partial)" — this is exactly the kind of partiality that discipline exists to catch.

**Recommended fix (small, test-only):** add one `it('editor mode routes keys to the editor', ...)` that
actually drives `F.session.press`, and retitle the existing mislabeled test to `'editor mode routes text
to the editor'` so it sits honestly alongside its console/project textinput siblings.

## Finding 2 — `F.reset()` exceeds the 14-line function-body hard limit (rules, mechanical)

`tests/helpers/input_fixture.lua:198-217`. Before this diff the function was 10 code lines (within
limit); this slice added the 5 native-slot restores + `CC.editor.input:clear()`, bringing it to **16**
code statement lines (19 including the 3-line comment), against `agents/rules.md`'s "Function body: 14
lines" **hard limit** ("When a limit is approached, redesign — don't raise the limit").

**Recommended fix:** extract the 5 `love.keypressed/textinput/keyreleased/mousepressed/mousereleased =
Controller._defaults.*` lines into a small `restore_native_slots()` helper (or similar), called from
`reset()`. Mechanical, no behaviour change.
