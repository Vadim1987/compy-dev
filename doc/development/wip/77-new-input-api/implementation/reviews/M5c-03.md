## The two flagged substitutions — independently adjudicated, both behaviour-safe

1. **`keep_history()` → unconditional `true`** (was `not self.oneshot`). **Safe.** Only
   `main.lua`'s project widget was ever constructed `oneshot=true` (verified every
   `UserInputModel(` site: console/search passed `false`, editor 2-arg ⇒ nil-falsy ⇒ already
   `true`). `keep_history` gates `_remember` (write), `reset(history)`, and
   `history_back`/`history_fwd`. The controller's `history_back`/`fwd` are wired **only** in
   `consoleController.lua:1129-1140` on the *console* instance; the project widget's up/down go
   through `cursor_vertical_move`, which never touches history. So for the flipped-to-true
   project widget the only new effect is *storing history entries nobody reads* — inert, as the
   comment claims.
2. **`UserInputView:draw()` identity check** (`self.controller ~= love.state.user_input_
   controller`, was `not is_oneshot()`). **Safe.** `love.state.user_input_controller` is set
   (`main.lua:371`) to exactly the project-widget controller — the sole former `oneshot=true`
   instance. The published singleton's view resolves the identity `true` ⇒ skip `update_view`
   (matching old oneshot=true skip); every other view ⇒ `~=` ⇒ update (matching non-oneshot).
   Read at draw time vs the old construction-time capture, but both resolve to the same truth
   at draw. No semantic drift.

Ancillary: the keypressed error-unlock set gained `left`/`right`/`space` — this is a **required
alignment** with AC-18's literal "unlocks on Enter/Space/arrows", not a widening beyond spec.

## Non-blocking observation (not a finding)

The `keep_history()` collapse means the project widget now silently accumulates unread history
in memory. Harmless today (nothing reads or navigates it), but it is a latent semantic
difference should the project widget ever gain history navigation — worth a one-line note if
that surface is built later. The implementor already surfaced this in "what will surprise the
architect", which is the correct disclosure. No action required for this chunk.
