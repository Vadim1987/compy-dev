## Per-trap findings

**Trap 9 — `after_submit` field-write, not a `show{}` key: CONFIRMED correct (all four).**
Verified `INPUT_CALLBACKS` (consoleController.lua:357-369) makes `after_submit` field-write-assignable,
while `OUTPUT_KEYS` (403-408) — the only keys `merge_output_keys` sticks — is
`on_text_entered`/`on_limit_reached`/`validator`/`highlighter`. So `show{ after_submit = fn }` is silently
dropped. Every migrated example uses a standalone `compy.input.after_submit = function() … end`; none
buries it in a `show{}` cfg. The re-prompt loop genuinely re-arms. No dead re-prompt slipped through.

**Trap 2 / AC-3 — `eval` stickiness: CONFIRMED by trace (not taken on faith).**
`apply_config` (userInputController.lua:212-214) calls `model:set_eval` **only if `cfg.eval`** is truthy;
`hide()` (301-303) only nils `love.state.user_input`; `clear_input()` (userInputModel.lua:344-351) resets
text/selection/cursor/custom_status/history but **never the evaluator**; the model is a single persistent
singleton (main.lua:363). So tixy's initial `show{ eval = InputEvalLua }` survives the bare
`after_submit` re-show — Lua highlighting stays armed round-to-round without a re-pass. The ledger's
surprise #2 trace is accurate. **Honest ceiling respected:** the highlighter is code-path-confirmed, not
pixel-verified (no framebuffer/`xdotool` in-container) — the ledger says exactly this and does not
overclaim "verified playable." Matches the M5c-05 precedent.

**Trap 5 — guess/valid validator wiring reproduces legacy behaviour: CONFIRMED faithful by construction.**
Legacy `validated_input(filters, prompt)` = `input(ValidatedTextEval(filters), prompt)`
(consoleController.lua:868-870), and `input()` (802-825) passes `eval = ValidatedTextEval(filters)` to
`show{}` while setting **no** `validator`. The migration passes the **identical** `eval =
ValidatedTextEval(filters)` and likewise sets no `validator`. Whatever the evaluator's validators enforce,
both paths receive it identically — the wiring is behaviorally equivalent by construction, not merely "a
validator is set." Delivery: migrated examples never call `user_input()`, so `self.result` stays nil and
`deliver()` (userInputController.lua:364-373) routes to `on_text_entered` — clean. (Note: submit
(380-389) gates only on `self.validator`; the evaluator-validator path is a pre-existing property equal on
both legacy and migrated sides, so it is not this chunk's concern.)

**Trap 10 — prompt persistence: NOT a regression (the note's suspicion is unfounded on verification).**
The review note suspected guess loses "Guess a number:" and tixy loses "function tixy(t, i, x, y)" on
rounds 2+. Traced the actual path: `apply_config` writes `model.custom_label` **only when `cfg.prompt ~=
nil`** (userInputController.lua:215-217); `custom_label` is written in exactly two places project-wide
(the constructor and that line — `grep` confirmed), and **nothing ever nils it** — `clear_input` leaves it
intact, `hide` doesn't touch the model. So `custom_label` is **model-sticky, exactly like `eval`**:
- guess's bare `show{}` re-show → `clear_input` runs (no text) but `custom_label` = "Guess a number:"
  persists → prompt shows every round.
- tixy's `show{ text = … }` re-show → no `clear_input`, no `prompt` key → `custom_label` = "function
  tixy(t, i, x, y)" persists → label shows every round.
The consoleController comment "prompt/text/cursor … never sticky **at this layer**" (410-413) refers only
to the surface pending/merge mechanism, **not** the model's `custom_label`. No drift; no corrective pass.
