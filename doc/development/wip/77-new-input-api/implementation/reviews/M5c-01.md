## Scrutiny of the six flagged items

1. **`chain_native` return propagation — REQUIRED, not a design change.** ✔ AC-2/AC-36(b) demand a
   native (a tier-3 install path) can consume via truthy return. M4's `wrapped_native` discards the
   return; a chain tier cannot. `chain_native` (controller.lua:~140) is the C3/C14 remark made
   load-bearing — it implements the spec's truthy-propagation contract, not new semantics. `wrap`/
   `wrapped_native` are retained for the fire-and-forget pointer path. **No escalation.**
2. **Removed legacy `if not self.result and running` textinput gate — genuinely superseded.** ✔ The
   removed gate is replaced by `_is_hidden_overlay()` (shown ⇒ edit, hidden ⇒ no-op). No green row
   asserts the old suppression. The `#deprecated` legacy-submit rows (spec:364, 468) still pass for
   the right reason: `input_text` sets `love.state.user_input`, so `_is_hidden_overlay` is false and
   the shown widget edits; the oneshot/`push('userinput')` machinery is untouched (chunk 3 owns it).
3. **`keys_pressed` proxy `pairs` yields nothing under LuaJIT/5.1 — not a gap.** ✔ No AC/consumer
   iterates `keys_pressed`; every consumer reads by key and writes raise (the load-bearing AC-8
   contract, asserted at spec:900). Caveat logged as accepted debt.
4. **`active_keyboard_route()` accessor + `stop names the console` row kept green — the one deviation
   worth the human gate.** ⚠ E30 Scope-10(a) is explicit: *drop the C23 accessor assertion* and
   *retarget the row to AC-29 teardown*. The implementor kept both, deferring the whole thing to
   chunk 4. Reasoning is coherent: the AC-29-teardown retarget genuinely needs chunk-4 machinery
   (route-lifecycle is out of chunk-1 scope, commission Boundaries), and the accessor is read by the
   *uncommitted* `src/tests/autotest.lua` manual driver. **However:** the *drop the accessor
   assertion* half of E30 is independently achievable now — the behavioural end-state is already
   covered green, without the accessor, by the PRESERVE row `the console receives after stop`
   (spec:332). So keeping `stop names the console as restored route` (spec:703, asserting
   `active_keyboard_route() == CC`) preserves exactly the C23 surface E30 said to retire, justified
   by a driver that is not even committed. **Ruling:** a legitimate-but-imperfect carve seam — the
   AC-29 retarget must wait for chunk 4, but the accessor could have been dropped now with no
   coverage loss. Production behaviour is correct and independently guarded, and the deferral is
   documented (outcome surprise #8) with a pointer to chunk 4. **Not blocking on its own**; logged as
   **planned** debt and flagged here so the human consciously blesses carrying the C23 accessor +
   its REVIEW marker (controller.lua:998) one chunk further.
5. **Manual live-LÖVE check not run — adequately compensated.** ✔ The `#m5c` rows drive the real
   `love.handlers.*` gateway installed by production `Controller.setup_callback_handlers`, through
   `Controller.set_user_handlers`/`occupy_keyboard` → `pic:keypressed` → `_dispatch` → tiers → sink
   (input_session.lua fires real events, never a controller shortcut). This is the same path a
   keystroke takes; combo-fires, truthy-intercepts, falsey-falls-through, native-while-shown, and
   hidden-no-mutation are all exercised end-to-end. Full 4-mode + turtle/maze hand-play is chunk 5.
6. **Scope fence — `consoleController.lua` justified; model/view correctly skipped.** ✔
   `compy.input` is assembled in `consoleController.lua:get_compy_input` — this *is* the "compy
   namespace setup" the spec Files list names, and AC-33's guard + the `handlers`/`on_*` surface must
   live there. In-scope. Skipping `userInputModel.lua`/`userInputView.lua` is correct: their changes
   (oneshot removal, `is_at_limit` extension, view snapshot) all belong to chunks 2/3 and are
   explicitly out of chunk 1. The internal hidden-check + uniform signatures landed at the controller
   layer (`userInputController.lua`), which is where they belong.

  works and is tested; the wholesale-replace refusal is defensible hardening. Noted for the architect,
  not a defect.
