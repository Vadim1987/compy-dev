### 2. CHIEF ITEM — finding-2 became a behaviour change; **verdict: SAFE / in-scope** — ✔

`src/controller/userInputController.lua`. The implementor did **not** just wrap the
over-length `-- REVIEW:` marker; they installed the noop default it suggested: `new()` now
seeds `on_limit_reached = noop` (`:17`), `require("util.lua")` added (`:5`), and `emit_limit`
dropped its `if on_limit then` guard to become the unconditional alias
`self.on_limit_reached(dir, scope)` (`:328`). I scrutinised this hard:

- **Cannot clobber a user-set callback.** The overlay controller is a **true singleton**
  constructed once (`main.lua:364` → `love.state.user_input_controller`); `show()`/`hide()`
  only toggle `love.state.user_input`, never recreate the object (`:275-291`). So `new()`'s
  seed runs once, before any write. `apply_config` (`:216-218`) sets `self.on_limit_reached`
  **only** `if cfg.on_limit_reached ~= nil` — it never resets to `nil`/`noop` — so a
  field/config-set callback **persists across a `hide()`→`show()` that omits it**. The seed
  moved the pre-any-write default from `nil` to a no-op function; nothing else moved.
- **Field-write path re-forwards on every show.** `get_compy_input().show()`
  (`consoleController.lua:415-424`) stores each output key in its own `state` table and
  re-injects `next_cfg[k] = state[k]` on every `show()`, so a `compy.input.on_limit_reached
  = fn` write reaches `apply_config` each activation. No clobber via that path either.
- **Consistent with the ratified shape.** R12/AC-14 hold: `emit_limit`'s return is
  discarded, and `noop` returns `nil` (ignored) — no chain meaning. This is an **internal
  instance-slot seed**, not a new *public* default needing a named consumer (guardrail 5):
  `compy.input`'s reads still resolve `state[k]` (unset ⇒ `nil` to the project), untouched
  by the controller-side seed. It is orthogonal to M5c-01's caution against a stored noop in
  the tier-3 `on_* or native` precedence — `on_limit_reached` has no native counterpart.
- **No allowlist widening / `__newindex` bypass.** `INPUT_CALLBACKS` still has exactly the 7
  keys (`consoleController.lua:352-360`); the seed lives on the controller instance, wholly
  separate from the surface's guarded `state`. AC-33 boundary intact.
- **"No callback set ⇒ nothing observable" still holds.** The console-REPL and editor-input
  `UserInputController` instances (never wired to `compy.input`) always run the noop default
  on boundary presses — previously the `nil` guard skipped, now `noop()` fires nothing. Same
  net effect; existing editor/console navigation rows exercise this path and stay green.

The safe fallback (note + debt-log) was available, but the installed default is demonstrably
safe, so the cleaner in-scope resolution is acceptable. Commit type `fix(input):` is right
for a behaviour change. **No finding.**
