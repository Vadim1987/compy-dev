1. **AC-3/AC-4 two modes — PASS (the subtle one).** Active `configure` feeds
   `UserInputController:configure` a hard-coded five-key literal
   (`prompt/highlighter/validator/on_text_entered/on_limit_reached`) — `text`/
   `cursor`/`eval`/`result` are never read off `cfg`, so they cannot reach any
   mutation path. Test `configure leaves text/cursor untouched … even mixed
   with a live field` proves cursor stays `(1,2)` (not even clamped to 99 →

## Judgment calls — assessed, both clean

- **`cursor` via `open_fresh`, not `apply_config`.** Correct call. It keeps the
  already-over-limit `apply_config` (27-line body, pre-existing debt) untouched,
  lands `cursor` at the right place (activation policy, applied after text per
  spec.md §3), and stays under 14 lines. The reachability comment ("kept out of
  `apply_config` so the live-reconfigure path can never reach it") is accurate
  and is itself part of the AC-3 inert guarantee. The flagged side effect —
  bare `show({cursor={l,c}})` now works — closes a real pre-existing spec.md §3
  gap (the `cursor` field was documented but never implemented for direct
  `show()`), is necessary infrastructure for hidden-configure, and introduces
  no wrinkle. Not a scope violation.
- **`clear` composed at the wrapper** (`ui:clear()` + `ui:update_view()`)
  rather than a dedicated controller method. Justified: `UserInputController:
  clear()` has four live `editorController` callers, so not perturbing it is the
  right instinct; the wrapper composes two existing public methods. Minor
  asymmetry with `configure` (which got its own method), but harmless and
  reversible.
- **`cursor` wire shape `{line, col}` positional array** (`cfg.cursor[1/2]` →
  `set_cursor_pos(line, col)`). Consistent with M7-01's `set_cursor(line, col)`
  / `get_cursor() → line, col` positional signatures. Reasonable and reversible.
