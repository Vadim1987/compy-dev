## Findings

### Finding 1: Incomplete Slot-Sharing Coverage (Spec/Trap Violation)
- **Requirement:** *"Conversely, a real settability assertion (config key and field both reach the same slot) **must** exist for all four outputs."* (Review trap 2).
- **Issue:** The test [`show(config) and fields share one output slot`](file:///repo/tests/input/input_contracts_spec.lua#L1121-L1131) verifies only `on_limit_reached` and `highlighter`. It completely omits slot-sharing assertions for `on_text_entered` and `validator`.
- **Corrective Action:** Extend the slot-sharing test (or add sibling assertions) to verify that `on_text_entered` and `validator` also reach the exact same slot through both `show(cfg)` configuration keys and direct `compy.input.<field>` assignments.

### Finding 2: `UserInputModel:is_at_limit` Exceeds function-body limit (Rules Violation)
- **Requirement:** Function body must be ≤ 14 lines (Hard limits in `/agents/rules.md` and `doc/development/conventions/code.md`).
- **Issue:** [UserInputModel:is_at_limit](file:///repo/src/model/input/userInputModel.lua#L559-L583) has a body length of 23 lines.
- **Corrective Action:** Refactor `is_at_limit` to comply with the 14-line hard limit. The following 14-line body redesign maintains identical correctness:
  ```lua
  function UserInputModel:is_at_limit(dir, scope)
    local n = self:get_n_text_lines()
    local cl, cc = self:get_cursor_pos()
    if not dir then return cl == 1 or cl == n end
    local req = (n == 1) and 'input' or (scope or 'input')
    if dir == 'up' then return cl == 1 end
    if dir == 'down' then return cl == n end
    local line = self:get_text_line(cl)
    local line_end = string.ulen(line) + 1
    if dir == 'left' then
      return cc == 1 and (req == 'line' or cl == 1)
    elseif dir == 'right' then
      return cc == line_end and (req == 'line' or cl == n)
    end
    return false
  end
  ```
