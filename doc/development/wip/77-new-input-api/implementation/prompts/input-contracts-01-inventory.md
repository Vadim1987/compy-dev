A single factual inventory at:

Fill the schema below. **Every claim carries a `file:line` citation.** Where you verified by running or

1. **The gateway** — what installs `love.handlers.{keypressed,textinput,keyreleased,mouse*,touch*,
   wheelmoved,userinput}`, when in boot, and its lifetime (permanent vs reinstalled).
2. **`app_state` enumeration** — every value the codebase uses; for each: what sets it (the transition
   sites) and what it means operationally.
3. **Slot ownership (the base sink)** — who owns each `love.<event>` slot in each `app_state` (default =
   which controller?); how a running project overrides it (`set_handlers`/`hook_if_differs`/`wrap_handler`);
   exactly **how and when** it is **restored** on project stop; the role of `_defaults` and `_supported`.
4. **Per-event routing** — for **each** event type (keypressed, textinput, keyreleased, mousepressed,
   mousereleased, mousemoved, wheelmoved, touchpressed/released/moved): the exact path through the gateway
   — overlay sink vs base slot, whether delivery is **EXCLUSIVE** (one) or **BOTH** (overlay *and* slot),
   the order, and any state guards (e.g. `app_state == 'inspect'`).
5. **`user_input` read/write sites** — every place `love.state.user_input` and
   `love.state.user_input_controller` are set / cleared / read (incl. `get_user_input`, `clear_user_input`,
   `handlers.userinput`, `show`, `hide`).
6. **Overlay (widget) lifecycle** — `show(cfg)` / `hide()` behaviour: the `{ M, C, V }` shape it writes,
   `force` semantics, the already-active no-op, any warn-on-suppression.
7. **Global shortcuts** intercepted at the top of `keypressed` — list each (keys + modifiers + effect) and
   state whether it is **consuming/exclusive** or whether the key **still flows on** to the sink.
8. **`keys_pressed` + `combo_string` + `isrepeat`** — how the held-key table is maintained; what
   `combo_string` produces; **where `isrepeat` is dropped or suppressed and at which signature**.
9. **Legacy solicitation path** — `input_text` / `input_code` / `user_input` (+ `r:is_empty()` polling) and
   any `Log.warn` guards.
10. **Mouse/click specifics** — single/double-click detection, drift tolerance, the overlay-AND-project
    double-delivery for mouse/touch.
11. **Doc-vs-code discrepancies** — a list of every place `user_input.md` (or the other docs) is wrong,
    stale, or silent relative to what you found in code.
