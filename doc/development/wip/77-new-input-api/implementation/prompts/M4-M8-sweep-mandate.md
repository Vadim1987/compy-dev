## Mandate: continue-if-ok

Human ruling (2026-07-02, brainlab session 31): sweep milestones back-to-back; no synchronous human
gate between each one. **Continue automatically to the next milestone only when ALL of:**

- the milestone's own prompt's acceptance criteria are met and self-verifiable — suite green at the
  counts its spec/prompt commits to, manual-mode verification done where the prompt requires it (M4
  requires four-mode manual verification), every DoD disposition applied, nothing silently deferred;
- no design churn / real judgment call surfaced. `implementation/README.md`'s own escalation clause
  already names the stop condition: *"If a milestone proves cognition-heavy or human-driven (design
  churn, real judgment calls — e.g. the integration-heavy M4 gate removal or M6 boundary model), do
  not force it through the black box."* M4 and M6 are explicitly flagged as candidates — treat that
  as a live check on those two, not a formality;
- no unresolved **human-ruling item** blocks the milestone (check `entrypoints.md` + the milestone's
  own spec/prompt for "ruling required" markers before starting it — e.g. M4's keyreleased-tier line
  is already resolved: ships **descope-with-note**, do not re-litigate it).

**STOP (hard) and hand back** to the human / a future brainlab orchestration session when:

- a milestone's suite doesn't converge green after a reasonable, recorded attempt — don't loop
  indefinitely; record what was tried and why it didn't converge;
- a genuine judgment call appears that isn't already dispositioned — scope ambiguity, a design
  decision the frozen spec doesn't answer, an irreversible architecture choice;
- M4 (or any milestone) reports it "cannot be integrated cleanly" per its own prompt's escalation
  clause;
- the sweep reaches the end of **M8** — the whole feature is done, that's a stop regardless of "ok".

Each stop is a **real** stop: write the outcome/report artifact (below), then end the session rather
than idling — the human resumes explicitly, same as any brainlab re-entrance.

## Per-milestone loop

For each milestone `MN` in order `[M4, M5a, M6, M7, M8]`:

1. **Orient.** Read `design/roadmap.md`'s entry for `MN`, the frozen `design/spec/MN.md` (+ any
   already-commissioned adjacent `MN-NN` closure specs — `M6-01-oneshot-snapshot.md`,
   `M7-01-retarget.md`, `M8-01-dead-text-input.md` already exist), `notes/input-contracts.md` (doc A)
   for the current contract baseline, and `entrypoints.md`'s entry for `MN` for carried rulings.
2. **If `implementation/prompts/MN.md` doesn't exist yet** (true today for M5a/M6/M7/M8 — only M4's
   is commissioned): author it yourself, mirroring `implementation/prompts/M4.md`'s shape (the
   7-section template in `implementation/README.md` § "The prompt template"), grounded strictly in
   the frozen `design/spec/MN.md` — never invent scope. Per `design/agents/process.md` §9.2, a
   milestone introducing new behaviour needs a **Tier-2 test-first step** (acceptance tests authored
   from the spec → red → implementation turns them green, just-in-time, not pre-authored). You may
   delegate the test-authoring half to a Sonnet subagent (the "cheaper-model rule" — little
   open-ended reasoning, transcription from a fixed spec) but keep spec-fidelity judgment yourself.
3. **Execute** the Do-section — yourself or via Sonnet subagent(s) for mechanical portions
   (implementation grind, running `busted tests`, fixing mechanical breakage). Same triage discipline
   already used in M4-0-05: mechanical fixes only; anything semantic **stops and gets recorded**,
   never silently weakened or deleted.
4. **Record the outcome** — `implementation/outcomes/MN.md`, matching the existing shape (commit
   refs, files changed, real verification counts, surfaced gaps).
5. **Self-review** against the milestone's own acceptance criteria + roadmap Contract before deciding
   continue vs. stop — you are standing in for the independent Opus review this once. If budget
   allows, spawn a Sonnet or Opus subagent to play adversarial reviewer against the diff + outcome
   before certifying "ok" (mirrors `agents/review.md`'s role) rather than certifying your own work
   unchecked.
6. **Commit locally** (Conventional Commits, no push) — one commit set per milestone, so every step
   stays independently revertible even though no synchronous human gate ran on it.
7. **Track** (below), then either continue to `MN+1` or stop per the mandate.

## Context discipline

Don't rely on mid-conversation auto-compaction/summarization to control token spend — it's lossy and
unpredictable about what survives. Treat **each milestone boundary as a hard context reset**, the
same way the execution plane already works: after step 6/7 of a milestone, end that unit of work: the
**next** milestone should start from a **fresh context** that reads only (a) this mandate, (b) the
track/report just written, (c) the next milestone's own prompt/spec — not the accumulated
conversation history of prior milestones. Prefer an explicit new session/sub-session per milestone
over one unbroken conversation running all five. The written artifacts (outcomes, track, report) are
the carry-over mechanism, not conversation memory — this is more disciplined than summarization and
matches the "complete-by-construction / legible" bar this project already converged on for the input
contract suite.
