**Verdict:** the problem is **adherence, not capability**. MCP was confirmed running and usable;
Sonnet just judged the LSP not worth it and grepped instead — and the doc-first rule it skipped was

## The adherence gap (confirmed empirically)

- MCP server (`lua-lsp`) was **up and the agent could call it** — not a wiring/health failure.
- It still used grep. Self-reported cause: **habit/inertia**, and a judgment that LSP wasn't useful
  for the (multi-symbol, exploratory) query in hand.
- The doc skip is the sharper signal: the doc-first rule **exists in two rule files** and was still
  ignored. ⇒ adding more imperative text is the wrong fix; salience/framing/triggering is.

## Token-churn is the wrong lever; correctness is the right one

| | Token-churn framing | Correctness framing |
|---|---|---|
| Felt by the model mid-task? | **No** — unmeasurable, so unactionable (this is *why* "cuts token churn" failed) | **Yes** — "did I miss a caller" is concrete |
| Savings guaranteed? | **No** — LSP calls cost tokens too; a thin Lua result forces a re-grep = **double spend** | n/a — the win is accuracy, not bytes |
| Stakes on a modest codebase | low / bounded — over-optimizing has low EV (the "stop worrying" case is legitimate) | high for *this* featureset |

## Why this featureset is the genuine high-value case

Unifying controller topology + changing Lua event propagation **is** cross-cutting impact analysis:
"who calls this controller method", "who handles/propagates this event", "what breaks if I rewire
this". That is exactly `find-references` / `call-hierarchy` — the **highest-payoff** LSP use (see the
per-mode table in [`mcp-lsp-tooling.md`](mcp-lsp-tooling.md)). Grep gives string matches; LSP gives
the call graph. The motivator is **not missing a caller during a refactor**, which dwarfs token economy.

### Refactor caveat — LSP *with* grep, not *instead of*

For dynamically-typed Lua (sparse EmmyLua annotations, `{M,C,V}` scaffolding, love2d globals)
`find-references` can be **incomplete**. An incomplete ref list that you *trust* is worse than grep,
because you silently miss a caller. So for completeness-critical sweeps in a topology refactor:
**LSP for accurate structure cheaply + grep as backstop, cross-checked.** ("Strong hint, not ground
truth" — already stated in [`mcp-lsp-tooling.md`](mcp-lsp-tooling.md).)

## Recommendation — middle path (don't overoptimize)

1. **Reframe the rule once**, around correctness/impact for cross-cutting queries (not token-churn).
   Encode the trigger Sonnet itself articulated: *exploratory/multi-symbol → grep first; known symbol
   in hand → LSP defs/refs; impact / "who calls / what breaks" → find-references / call-hierarchy;
   architectural / "how does X reach Y" → read `doc/development/` before spelunking.* Frame the doc
   rule as "on-demand, **and architectural/why questions are the trigger**" (the current "load on
   demand, not upfront" reads as *don't bother*).
2. **Observe** a couple of real transcripts on this featureset — did it use find-references for "who
   handles this event"? If yes → done, stop worrying.
3. **Only if it still reverts** despite a healthy MCP + correctness-framed rule → a decision-time hook
   (e.g. `PreToolUse` on Grep of a bare identifier → "you have a symbol; `lua-lsp` defs/refs is
   AST-accurate here"). Don't pre-build this; and don't push so hard it reaches for LSP when grep is
   genuinely better (over-steering wastes tokens the other way).

## Reframe — single agent, human picks the mode (supersedes multi-agent shape)

The "three agents" framing (orchestrator / dev / reviewer + a separate Q&A agent) in
[`mcp-lsp-tooling.md`](mcp-lsp-tooling.md) is **collapsed**: one human-driven `codeinspect` container,
the human deciding per chat what to work on — **development**, **code inspection**, or **implementation
review**. No agents in parallel. The **per-agent LSP value table still holds — now read per-mode**:
inspection/review-mode = highest LSP payoff (impact analysis); development-mode = bounded-yes (catch
errors, cut blind grep/read). Same conclusion, one re-roled agent instead of three.
