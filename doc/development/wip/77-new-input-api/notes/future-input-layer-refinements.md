## Considerations

- **Separate analytical reflection from true inputs + verdicts.** The input layer currently
  mixes raw inputs, inferred/analytical reflection, and verdicts. These are different kinds and
  should be separated.
- **Analytical loops → maybe a separate `analysis/` directory, off the critical path.** Such a
  loop **captures work sourced in a specific contradiction** (one surfaced in `status.md` when
  the design does **not** converge) and **results in new 'inputs'** — i.e. *decisions on
  resolutions*. So the loop is: contradiction (in `status`) → analysis (`analysis/`) → new input
  (a resolution decision) → reprocess. Keeping it out of the critical path keeps the chain clean.
- **Structure the ingest by source.** For this topic specifically, the notes/inputs should be
  split into **stakeholder inputs** vs **architect inputs** (distinct authority/provenance).
- **Cleanup rule — don't duplicate inferred text into the ingest.** During cleanup, **inferred
  texts must be wiped from `notes/`** if they end up captured in `requirements` / `constraints` /
  `remarks` anyway. The ingest tier holds *raw* inputs; inferred/distilled content belongs
  downstream, not duplicated upstream.
