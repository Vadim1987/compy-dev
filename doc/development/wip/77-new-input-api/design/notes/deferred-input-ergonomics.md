# Deferred open question — the `show`/`configure`/`set_text` ergonomic form

_Generated by LLM(Claude Opus 4.8): 2026-07-06 (brainlab session35 — recorded on the owner's instruction at Gate 3);_
Status: **OPEN, deliberately deferred by the owner.** Not a blocker; not a design defect.

## The question

The input API exposes three overlapping ways to put/replace text and configuration on the widget:

- **`show(config)`** — activate, seeding `text` / `cursor` / callbacks (spec.md §3).
- **`configure(config)`** — live-update `prompt` / `highlighter` / `validator` / widget-output
  callbacks on an active session; `text` / `cursor` accepted-but-inert (spec.md §3, M7).
- **`set_text(text[, keep_cursor])`** — the live-write exception to `configure`'s
  text-immutability (spec.md §6, M7).

The **contract** for these is settled and ratified (spec.md §3/§6 — that ships in M5c/M7 as
specified). What is **not** settled is whether this is the most **ergonomic authoring shape** —
the split of responsibility between the three, the inert-vs-live text handling, whether a project
author finds the boundary intuitive.

## Why it is parked (owner's reasoning, 2026-07-06)

> "I am still not sure what the most ergonomic form of the configure/show/set_text relationship is,
> but prefer not to figure it out now — it would be easier to imagine and compare variants on the
> existing foundation."

I.e. this is a design-taste judgement better made against **running code** than on paper. Building
the ratified surface first gives a concrete foundation to prototype and compare alternative
ergonomic shapes cheaply.

## Where it will be revisited

The **console/editor migration** — already the designated venue for the next simplification round +
stakeholder input on dev-facing facets (Gate-2 closing ruling, design.md §2). This ergonomics
question rides that venue. The owner may also reopen it earlier under the standing
"human-reversal-is-in-bounds" principle (sweep mandate) if implementation makes a better shape
obvious.

Do **not** attempt to resolve or "improve" this in M5c/M7 — build the ratified surface; this note
is the parking record so the question is not lost.
