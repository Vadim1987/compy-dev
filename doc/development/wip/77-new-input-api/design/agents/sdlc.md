- context: **inline** — `context.md` is a full requirement×code matrix (architecture assessment), not a thin external pointer.
- outcome: **referenced** — the design lifecycle's world-out is the **converged `roadmap.md` + `spec.md`/`spec/` pair**; the *built* code is the downstream sprints' outcome (commits in the project repo). No separate `outcome.md`.

- estimates: a **derived, versioned node** off `roadmap`+`spec/` — `estimates.md`
  (+ `estimates.versions/`) holds per-milestone PERT and owns the current total; `roadmap.md` carries
  only the **frozen design-phase total** (historical artifact, never recalculated) + an
  **append-only total-estimated log** (one derived line per recalc, latest = live total) + a pointer.
  A topic-local refinement of canonical SDLC (which folds estimates into the roadmap node).
  Maintenance is a standing operational entrypoint (see [`process.md`](process.md) §7,
  [`../../entrypoints.md`](../../entrypoints.md)). *(Extracted — entrypoint **E10** landed, session 11,
  2026-06-18; `estimates.versions/version01` is the genesis baseline.)*
- review/status: the canonical edge-based `review`+`status` loop is **not run live** — the design is **converged** (E1, `sessions/.../session02/report.md`). The round-based history is frozen under `status/archive/`; `status.md` is the live, **versioned** dashboard and convergence is **derived** from its decision ledger + stabilization map.
