## Summary

- The design lifecycle is **iterative conceptual design with repetitive stakeholder
  feedback** → its outcome is a **converged roadmap + per-milestone specs**, not code.
- Its spine **matches canonical SDLC**: `input → context → requirements → design → spec →
  roadmap → (outcome = roadmap+spec)`. Your DESIRED FLOW and canonical SDLC have converged.
- It **deviates** in two deliberate ways: (1) `decisions.md` is a first-class pipeline
  node, (2) review is **round-based** (temporal episodes), not edge-based.
- The design is **converged** (E1). So the live control loop is retired; convergence is now
  **derived** from the per-decision status ledger in `decisions.md`, and the round history
  (`reevaluations/`, `validation/`) is kept as the audit trail.
- The **handoff edge** to implementation: `design.outcome (roadmap + spec/MN) →
  sprintNN.requirements`.

## 4. The two "round" axes — disambiguation (E1 finding, fixed in E4)

The provenance tags conflated **two distinct cycles both labelled "round 1/round 2"**. They
are now disambiguated wherever they appear (in `decisions.md` and here):

| Axis | What it is | Episodes |
|---|---|---|
| **Stakeholder rounds** | external approve/veto feedback against the proposal | **SR1** = `input.md` (2026-06-06); **SR2** = `input/stakeholder2_notes.md` (2026-06-10) |
| **Validation rounds** | internal edge-coherence checks of the chain | **VR1** report1 **FAIL** → VR2 report2 **PASS-WITH-NOTES** → VR3 report3 **PASS-WITH-NOTES** (all 2026-06-08) |

Convention going forward: write **SR1/SR2** for stakeholder rounds and **VR1/VR2/VR3** for
validation rounds; never bare "round 1/round 2".

## 5. Convergence is derived, not asserted (E1 finding, fixed in E4)

E1 found the convergence *status* lived in a hand-maintained prose header in the old
`decisions.md` that **drifted from the body**. E4 replaces it: the per-decision **ledger** in
[`../status.md`](../status.md) carries each ruling's authority + provenance, and the
convergence summary is a **derived** roll-up of that ledger, not a separately-maintained claim.
This makes "is the design converged?" checkable from the dashboard, not a prose assertion that
can rot.

## 6. The handoff edge to implementation

- **`design.outcome` = `roadmap.md` (the ordered milestones + estimates) + `spec/MN.md` (the
  per-milestone detailed specs).**
- Each `sprintNN/` is its **own canonical (edge-based) SDLC instance**; its `requirements`
  derive from one roadmap milestone + the matching `spec/MN.md`. Its outcome = commits in the
  project repo. See the topic [`../../README.md`](../../README.md) for the two-lifecycle model.
