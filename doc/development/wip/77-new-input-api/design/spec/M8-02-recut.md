## Summary — the slice in plain language

After this slice, the old way of asking the user for text is gone: the five legacy globals
(`user_input`, `input_text`, `input_code`, `validated_input`, `write_to_input`) no longer
exist, and with them the poll-a-reftable-every-frame idiom. Projects use `compy.input.*`
exclusively — show a widget with callbacks, get the submitted text pushed to you. The example
projects that used the old API are migrated (tixy and balloons first), and the feature is
complete: this is the terminal milestone.

## Contract

- **Removed globals** (no facades, no flags): `user_input()`, `input_text()`, `input_code()`,
  `validated_input()`, `write_to_input()`. The reftable / `is_empty()` polling idiom goes
  with them. Calling any of them afterwards is an ordinary `nil` call.
- **Replacements** (spec.md §9 mapping — the migration recipe):
  - `user_input()` → nothing to poll: the submitted text arrives via
    **`on_text_entered(text)`** (the widget's delivery callback), with `after_submit(text)`
    as the post-deactivation hook.
  - `input_text(p, i)` → `compy.input.show{ prompt = p, text = i, validator = <text-eval>, on_text_entered = fn }`
  - `input_code(p, i)` → same + Lua `highlighter`/`validator`.
  - `validated_input(fn, p)` → `compy.input.show{ prompt = p, validator = fn, on_text_entered = fn }`
  - `write_to_input(c)` → `compy.input.set_text(c)`
  - *(Validator/highlighter helper names — `InputEvalText` etc. — are current mechanism, not
    contract; wire whatever the codebase actually provides at commissioning.)*
- **`love.state.user_input`** is driven solely by `compy.input` activation state (mechanism,
  non-binding) — no separate legacy code path remains.
- **M8-01 folded in:** delete the dead `compy_namespace.text_input = input_text` nil write
  (`consoleController.lua`; grep-confirm no reader first). If a real `text_input` alias turns
  out to be wanted, that is a stop + gate round — never a resurrected nil write.
- **Migration scope:**
  - **Priority (release-blocking):** `tixy` (in-repo; `input_code` + `write_to_input` +
    `user_input`) and `balloons` (`input_text` + `user_input`; **foreign checkout — see
    Delivery mechanics**). Balloons' hint loop (re-show per hint + per-frame polling)
    becomes `show` once + `configure{prompt=…}` + `on_text_entered`/`after_submit`
    (continuous-session idiom, spec.md §5).
  - **Convert-or-exclude (owner's release call):** `repl`, `guess`, `valid` — trivial
    conversions; any not converted in time are excluded from the next release, not blocking.
  - **Already migrated (M5c — not this slice):** `turtle`, `maze`.
  - **Unaffected:** pure-native examples (`pong`, `life`, `paint`, `sapper`, `sine`, `clock`,
    `keyboard`, `drawdebug`) — natives keep working as chain participants (R7).
- **Delivery mechanics (Gate-3 ruling):** `src/examples/balloons/` is a **copied-in checkout**
  (own nested `.git`, untracked by this repo). Migrate it in place, but deliver as
  **uncommitted working-tree changes** — never commit inside it, never touch its `.git`; the
  outcome ledger lists the changed files; the human carries the patch upstream (mandate
  guardrail 7). `tixy` and the convert-or-exclude examples are tracked in-repo and commit
  normally.

## Acceptance criteria (verbatim, self-contained)

- **AC-1** None of the five globals exists in the project environment; calling `input_text`
  (etc.) fails as an ordinary `nil` call — no shim, no deprecation path.
- **AC-2** No code in the tree reads or writes the legacy reftable / `is_empty()` polling
  surface; the `compy_namespace.text_input` dead write is gone with no remaining
  reader/writer (M8-01).
- **AC-3** `tixy` runs fully on `compy.input.*`: code entry with highlighter/validator,
  live writes via `set_text`, submit observed via callbacks — no polling loop remains in it.
- **AC-4** `balloons` runs fully on `compy.input.*` using the continuous-session idiom
  (activate once, re-prompt from the submit hook) — no per-frame polling, no re-show-per-hint
  loop; delivered as uncommitted working-tree changes in its nested checkout.
- **AC-5** `repl`, `guess`, `valid` are each either migrated (running on `compy.input.*`) or
  explicitly marked excluded in the outcome ledger — the owner's release call, recorded, no
  third state.
- **AC-6** Pure-native examples still work unchanged (natives as chain participants).
- **AC-7** `love.state.user_input` reflects widget activation only; no legacy path drives it.
- **AC-8** Spec edge cases hold on the migrated examples: stop-while-active (silent hide,
  full reset), show-while-active (no-op + warn), validator-reject lock.
- **AC-9** Migration commits touch only in-repo files; the nested checkouts
  (`balloons`/`keyboard`/`maze`) have no new commits and untouched `.git` directories
  (mandate guardrail 7).
- **AC-10** Full suite green; example-migration coverage per the roadmap Test-coverage
  bucket (legacy globals gone = `nil` call asserted; priority examples exercised).
