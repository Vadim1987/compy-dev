## Contract (this milestone)

- **Named chains** (framework owns the middle, projects can't suppress it):
  - submit: `before_submit(keys_pressed)` → framework evaluate+store+`push('userinput')` →
    `after_submit(result)`. `after_submit` fires **only on successful evaluation** (not when the
    validator rejects).
  - cancel: `before_cancel(keys_pressed)` → framework `model:cancel()`+`push('userinput')`+hide →
    `after_cancel()`.
  - `before_*` return values ignored; ordering enforced by call sequence.
- **`framework_handlers['return']`** owns submit; **`framework_handlers['escape']`** fires the
  cancel chain and **dismisses unconditionally** (fixes today's "Escape clears but doesn't
  dismiss").
- **`oneshot` deleted** — both its jobs are now covered (activation by `show()`/`hide()` from M2;
  submit by `framework_handlers['return']` here). Remove the field from `userInputModel.lua`
  (~L15, ~L49) and the submit-path reads in `userInputController.lua`.
- **`on_limit_reached(direction, scope)`** fires when the cursor attempts to move past a boundary:
  - `direction`: `'up'`/`'down'` (first/last line) and `'left'`/`'right'` (first/last char).
  - `scope`: `'input'` (whole-input, existing `is_at_limit` semantics) or `'line'` (current-line
    start/end). Single-line collapses `line`→`input`. Always propagates (project + framework both
    observe). If the keypressed sink default was replaced, `on_limit_reached` no longer fires.
- **`UserInputModel:is_at_limit` extension** (~L558): from vertical-only whole-input to also
  report horizontal and line-scope boundaries; the existing vertical whole-input case unchanged.

## Acceptance

- All six hooks fire at the correct points with correct args; `after_submit` skipped on validator
  reject; eval-failure behaviour preserved (error highlight, input locked).
- Escape dismisses and fires `before_cancel`/`after_cancel`; `push('userinput')` fires on cancel.
- `on_limit_reached` fires for all four directions × both scopes; single-line collapses line→input.
- `oneshot` gone; submit still works via `framework_handlers['return']`; editor block-nav intact.
