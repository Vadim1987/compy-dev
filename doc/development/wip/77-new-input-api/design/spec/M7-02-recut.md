## Summary — the slice in plain language

After this slice, a project can steer the input widget programmatically while the user types:
change the prompt, validator, or highlighter mid-session (`configure`), wipe the content
(`clear`), and read or move the cursor and replace the text (`get_cursor` / `set_cursor` /
`set_text`). This is the surface that makes validator-reject flows jump the cursor to the
error, history-style navigation possible from `on_limit_reached`, and drafts restorable. It
is purely additive — no routing or dispatch behaviour changes.

## Contract

All under `compy.input`; the project never holds the widget object. Every refused call warns —
never a silent swallow (C2).

- **`configure(config)`** — live update of an active session. Same fields as `show()` minus
  `force`. Only provided fields change. Live-updatable: `prompt`, `highlighter`, `validator`,
  and the widget-output callbacks. `text`/`cursor` are **accepted but have no effect** on an
  active session (use `set_text`/`set_cursor`, or `clear()` + `show()`). Safe when hidden —
  takes effect on the next `show()`.
- **`clear()`** — clears content, cursor to start, no callback fires. No-op + warn when hidden.
- **`get_cursor()`** → `line, col` — 2D, 1-based, **source-line** coordinates (not
  wrapped/apparent). Returns `nil` when hidden.
- **`set_cursor(line, col)`** — clamped to the valid range; no-op + warn when hidden.
  Single-line callers pass `line = 1`.
- **`set_text(text [, keep_cursor])`** — replaces the active session's content (the
  live-write surface; the explicit exception to `configure()`'s text-immutability; supersedes
  the legacy `write_to_input`, removed at M8). `keep_cursor` truthy preserves the cursor
  position; else cursor to end. No-op + warn when hidden. Triggers a view update.
- **Model fix:** `UserInputModel:set_text` must honour `keep_cursor` (skip the unconditional
  jump-to-end when set).
- **Mutable boundary unchanged:** these are callable API — assignment to them errors loudly
  (established in M5c, spec.md §7). This slice adds no assignable surface.

## Riding decision — M7-01 (re-target boundary, folded in)

`configure()` deliberately **does not** re-target an active session's delivery callbacks'
*semantics* beyond what the Contract above allows — the M7-01 question ("can an active
session's result sink / evaluator be swapped live?") must be **decided and closed here**,
not left open. Default ruling (M7-01 Option B, KISS): `validator` and the widget-output
callbacks **are** live-updatable (that is the Contract above — one rule, no special case),
but `text`/`cursor` immutability via `configure()` stands, and no partial/silent application
path may exist: the contract and the code must agree exactly. Document the decided behaviour
in `doc/development/internals/` (no milestone ids in prose) and strike F-5 from
[`../../implementation/technical_debt.md`](../../implementation/technical_debt.md). If
implementation surfaces a concrete need to diverge from this default — **stop, gate round**
(mandate guardrail 1), never an in-slice ruling.

## Acceptance criteria (verbatim, self-contained)

- **AC-1** `configure{prompt='new'}` updates the displayed prompt on an active session
  without teardown — content, cursor, and callbacks untouched.
- **AC-2** `configure{validator=fn}` / `{highlighter=fn}` / `{on_text_entered=fn}` /
  `{on_limit_reached=fn}` take effect immediately on an active session; the next
  submit/boundary/keystroke uses the new function.
- **AC-3** `configure{text=…, cursor=…}` on an active session changes nothing in the session
  (accepted, inert) — and is applied on the next `show()` when given while hidden.
- **AC-4** `configure` while hidden is safe and applies on the next `show()`.
- **AC-5** `clear()` on an active session empties the content and puts the cursor at the
  start; no callback fires. `clear()` while hidden is a no-op + warning.
- **AC-6** `get_cursor()` returns `line, col` in 1-based source-line coordinates on an active
  session, and `nil` when hidden.
- **AC-7** `set_cursor(line, col)` moves the cursor; out-of-range values clamp to the valid
  range; while hidden it is a no-op + warning.
- **AC-8** `set_text(t)` replaces the active session's content and puts the cursor at the
  end; `set_text(t, true)` replaces content and preserves the cursor position (clamped if
  the new text is shorter); while hidden it is a no-op + warning; the view reflects the
  change without a re-show.
- **AC-9** Every refused call above produces a visible warning (log), never a silent return.
- **AC-10** Assigning to any of these functions (`compy.input.set_text = …` etc.) raises a
  loud error — the mutable boundary is unchanged.
- **AC-11** The M7-01 boundary is closed: the re-target behaviour of `configure()` toward an
  active session is exactly the Contract above, documented in `doc/development/internals/`,
  with F-5 struck from the tech-debt ledger; no path applies a `configure` change partially
  or silently.
- **AC-12** The contract suite's m7-family `pending` rows convert to live green; the full
  suite is green; no routing/dispatch behaviour change is observable in any app mode.
