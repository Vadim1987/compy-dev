## Contract

### C2T-1 — A test that drives the real submit path

Add a test (extend `tests/input/overlay_spec.lua` or a sibling) that:

- builds a **oneshot** singleton (`UserInputModel(cfg, InputEvalText, true)` + controller, as
  `overlay_spec.lua` already does);
- `show()`s it and gives it **distinctive non-empty** text (e.g. `set_text("REMEMBER_ME")`);
- performs a **real successful submit** — `model:handle(true)` — the path that pushes the `userinput`
  event and, per `userInputModel.lua:803`, leaves `entered` populated (it does **not** clear on
  submit). Mock whatever `handle` needs (`love.event.push` / `love.harmony`) so the submit runs;
- `hide()`s (the consumer closes the overlay on the event), then `show()`s again with **no `text`**;
- asserts `c:is_empty()` is **true** (and, if cheap, that `get_text()` does not contain the submitted
  value).

This must exercise `handle(true)`, **not** a `set_text → hide → show` proxy — driving the real submit
is the whole point.

### C2T-2 — Prove the test has teeth (fidelity check)

Because the fix already ships, C2T-1 is green from the start. Demonstrate it actually guards the
behaviour: temporarily remove/neutralise the clear in `open_fresh`
(`userInputController.lua:202-205`, the `if cfg.text == nil then self.model:clear_input() end`),
re-run, and confirm C2T-1 turns **red**; then restore the code. Record the mutate→red→restore in the
outcome (do **not** commit the mutation). If C2T-1 stays green with the clear removed, it is not
testing the real path — fix the test.
