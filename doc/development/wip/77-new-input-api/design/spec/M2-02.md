> live consumer still depends on**, and let a behaviour regression through because the suite never

> gap that hid the break.

## Contract (this corrective take)

### C-1 — Restore the full `{ M, C, V }` overlay handle (fixes F-1, blocker)

`love.state.user_input` must again carry the **full historical triade**, not a narrowed subset:

- On `show()` activation, set
  `love.state.user_input = { M = self.model, C = self, V = self.view }`
  (the singleton already owns both — `self.model` from construction, `self.view` from
  `init_view` in `main.lua`). The current code sets `{ C = self }`
  (`userInputController.lua:212`).
- This is **mandatory, not optional**. The running-project draw overlay at
  `src/controller/controller.lua:401` calls `ui.V:draw()`; with `.V` absent, any running project that
  opens an input over its own `love.draw` faults with `attempt to index a nil value (field 'V')`.
  Shipped examples `turtle` (`input_text`) and `tixy` (`input_code`) both hit this on the input frame.
- Do **not** instead rewrite the overlay to reach the view through the controller. That is a deliberate
  interface change better weighed in M4 (when the controller owns dispatch); doing it here would be
  exactly the kind of unrequested restructuring that caused this regression. Restore the handle the
  overlay already expects.

### C-2 — Restore empty-on-fresh-prompt behaviour (fixes F-2, confirm at runtime)

The pre-M2 per-call widget built a **fresh `UserInputModel` every session**, so each prompt opened
empty unless an `init` value was given. The persistent singleton model breaks this: after a oneshot
submit the model keeps its text (`UserInputModel:handle` does not clear `entered` on submit), and a
re-prompt with no `init` (e.g. `input_text("TURTLE")` re-requested each idle frame) re-opens
pre-filled with the prior entry.

- A **fresh activation** (a `show()` that transitions `love.state.user_input` from `nil`/inactive to
  active) with **no `text`/`init` supplied must start empty** — restore the historical "empty each
  time" behaviour.
- The clear belongs at the **fresh-activation (or submit) boundary**, **not** in `hide()` and **not**
  in the already-active `force` path — `M2.md` deliberately specifies `hide()` *preserves* content and
  `show({force=true})` *preserves* when no `text` is given. Those two semantics stay exactly as
  `M2.md` defines them; only the inactive→active transition gains the clear.
- **Confirm at runtime**, not just by unit test: drive `turtle` (or `tixy`) through submit →
  re-prompt and observe the widget opens empty. The review's trace is strong but submit timing is
  involved.

### C-3 — Tests first, and they must cover the previously-uncovered path

Per [`/agents/development.md`](../../../../../agents/development.md) ("start with breaking tests, then
fix by implementation"), the corrective tests are written **before** the fix and must **fail against
the current code**:

- **Overlay-shape test (the gap that hid F-1).** Assert `love.state.user_input` carries a usable
  view after `show()` — at minimum that `.V` is present and drawable; ideally drive the actual
  overlay (`ui.V:draw()`, or the real `set_love_update` draw wrapper) against the **startup
  singleton**, not an ad-hoc `make_ctrl` mock. Take 1's `singleton_spec.lua` validated method
  semantics on throwaway controllers and never touched `main.lua` wiring or the `love.draw` overlay —
  which is precisely why F-1 passed CI.
- **Empty-on-reprompt test (C-2).** Submit a oneshot session, then `show()` again with no `text`, and
  assert the model opens empty.
- Both tests must be **red before** the C-1/C-2 changes and **green after**. Keep the existing 11
  method-semantics tests passing unchanged.
