## Why the corrective (the char-net tested the wrong thing)

The `-0` net pinned **per-example input behaviour** (tixy submits `1+1`, balloons `start`, turtle Esc
clears, maze `is_empty` flips) as a "safety net." Three faults, surfaced by the session-24 human review:

1. **It guards a non-obligation.** Product backwards-compat is **withdrawn**; the examples are
   **migrated** at M8. Freezing their current input behaviour pins something we have explicitly decided
   is free to change — the exact M2-take-1 mistake (product-BC judgement where only build-continuity
   applies), re-encoded as tests.
2. **It mostly re-tests covered ground.** The example/overlay/editor *component* behaviour is already
   covered — `overlay_spec` (submit/reprompt), `singleton_spec` (show/hide/force/warn), `keys_pressed_spec`
   (held-keys table), `editor_spec` (editing, block-nav) — and those specs **drive the controllers
   directly**. Re-skinning the same overlay path under five example labels added duplication, not teeth.
3. **It missed the one untested surface that matters.** No existing spec exercises the **integrated
   `love.handlers` → controller routing** (the overlay *gate*) or **slot ownership/restoration** — and
   that gate is exactly what M4 rewrites. The net's "native reached" rows asserted `session.press` calls
   a local lambda (a tautology), not that a real controller received the event.

Build-time continuity (in force) requires only that the running system **not fault** at each milestone
boundary — REPL, editor, and the examples keep working — **not** that their exact input semantics are
frozen. The honest M4 guard is therefore *routing-level*, not *behaviour-characterization*.

## The front-tests

Two groups. **Naming rule (codified convention):** test descriptions carry **no milestone / sprint ids**
(`M4`, `D-9`, "characterization net" are banned) — tests are self-contained product code; name them by
behaviour. The file should be renamed to a behaviour name (e.g. `input_routing_spec.lua`) — confirm at
authoring.

### Group 1 — must-not-degrade (regression smoke, **green now and after M4**)

Drive through the installed `love.handlers.*` slots (the gate), assert the **real** consumer received —
agnostic to the gate mechanism, so they hold across M4's rewrite.

1. **console mode, no overlay** → `keypressed`/`textinput` reach `ConsoleController` (the REPL still
   receives input).
2. **editor mode** → `keypressed`/`textinput` reach `EditorController`.
3. **overlay active** → the event reaches the singleton sink **and the native handler is not also
   invoked** (no double-delivery / routing exclusivity).

Plus keep the **editor vertical block-nav at buffer limit** row (via `editor_session.lua`, unchanged) —
M6 rewrites `is_at_limit` to line scope and must not regress whole-input block-nav. Reframe its comment
to say it exercises block-nav **indirectly** through the at-limit condition.

### Group 2 — must-be-implemented-by-M4 (carried `pending` now → M4 greens them)

These describe behaviour that does **not** exist yet (so they cannot be green against current code);
carry each as busted `pending(...)` with a greppable `-- DEFERRED (0.1.0-m4): …` marker, exactly as the
old single forward assertion did, so the suite stays green and the pre-commit hook passes. M4 converts
each `pending(...)` → a live green `it(...)`.

4. **gate-removal payoff** — with a project running and the singleton active, **project key events reach
   `ProjectInputController`** (today they are silently dropped by the `if user_input then` gate).
5. **slot ownership/restoration** — `ProjectInputController` occupies the keypressed/textinput slots
   during run; on project **stop** the slot is restored to `ConsoleController`.
6. **native coexistence** — a legacy project (defines native `love.keypressed`, sets no `compy.*`
   surfaces): native handler fires when the singleton is **hidden**, the text sink receives when
   **visible** (the lifecycle-split wrapper M4 auto-provisions).
7. **`isrepeat` threading** — `isrepeat` reaches the keypressed path (the E20 regression-undo M4 threads
   at `controller.lua:554`). This is the *same* forward assertion the `-0` net already carried; it stays.
