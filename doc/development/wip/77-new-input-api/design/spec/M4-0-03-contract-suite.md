## Why (the suite was never authored from the contract)

The contract record is sound (validated → cold-revalidated →
rulings landed → s27 vocabulary reconciliation). But the test
suite **grew incrementally** across M2 / M4-0-01 / M4-0-02 —
each slice mirrored the prior slice's idiom — so it still tests
**this sprint's mechanism**, which the M4/M5 routing rewrite
will churn. It therefore guards little that survives the
rewrite, and reads as implementation-juggling
(`singleton_spec` asserts `love.state.user_input`/`.C`/identity;
`input_routing_spec` carries ~175 ln of standup boilerplate +
a method-name spy).

The governing reason this matters (architect, s27): the
framework has had **no written input contract** — implementation
was its own de-facto spec, so any change was self-legitimizing
and nothing could call a change illegitimate. An **executable**
contract is the fix a prose record can't be: a doc drifts
silently, a failing test objects loudly. This suite pays down
that root debt. It is **not** gold-plating, and it is **not**
"one more test pass" — it is the missing source-of-truth +
the TDD scaffold for M4/M5.

**Feasibility (A8) — resolved.** TDD-against-a-designed-API is
valid: the forward surface (`ProjectInputController`,
`on_key_pressed`, callbacks) is written **now as `pending`**,
greened by M4/M5. The present surface (`compy.input.show/hide`,
force, text — landed at M2) is drivable today. So the suite is
authorable now; nothing is gated. The earlier "can't test what
isn't built" read was a category error.

## Vocabulary (binding — see the glossary)

Use the canonical terms from
[`input-contracts.md` §2 glossary](../../notes/input-contracts.md):
**route** (the consumer an event is dispatched to; exactly one
per keyboard/text event), **sink** (a route's default/last-resort
disposition — implementation-light), **widget** (the
route-managed input surface). Test/`describe` names use these;
**no** "base sink", no overlay-gate vocabulary, **no milestone /
sprint ids in test descriptions** (C3).

### Bucket D — CHARACTERIZE-PROVISIONAL (factual today; will change)

Current behaviour **expected to change** — documented so the
change is visible, never silent; **not** a preserve-contract.

- CP1 inspect (§3.4, R2) — under `inspect` the console owns the

  not dead.

**Discipline (s27 D-β):** each CP test asserts **only the
verifiable current behaviour**. Any "how it should become" is an
**assumption** (zero stakeholder input on inspect/wheel) — record
it as a comment, **never** assert it. Tag the block clearly so a
deliberate M4 change reads as expected, not regression.

## Authoring discipline (what makes it read as contract)

1. **Fixture carries the standup.** The MVC/gfx/font boilerplate
   moves into the harness (`input_session.lua` + a small fixture)
   so each test reads as a contract statement, invoked in ~1
   line. The ~175 ln of inline standup in today's
   `input_routing_spec` is the symptom of a too-thin fixture, not
   an inherent tax.
2. **Assert at the boundary, not the method.** Replace the
   `record_calls(obj, name)` method-name spy with **observable
   outcome** (state/text changed) or a **public-callback**
   receipt (`compy.input.on_key_pressed = function(k) … end`).
   Where proving exclusivity needs a "did-not-receive" check, spy
   at the public seam, not an internal method.
3. **Outcome, not mechanism.** No assertions on
   `love.state.user_input`, `.C`, slot identity, or gate
   internals **as behaviour** (those live only in Bucket C,
   labelled). EXCLUSIVE = "exactly one route received"; BOTH =
   "widget and route both received".
4. **Migrate, don't accrete.** `singleton_spec` / `overlay_spec`
   / `input_routing_spec` content is **re-homed** into the
   buckets (behavioural → P/I rows on the public surface; NFR →
   Bucket C). The old files are superseded, not extended.
