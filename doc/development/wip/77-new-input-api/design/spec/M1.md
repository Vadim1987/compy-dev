## Contract

### `Controller.keys_pressed`

A plain Lua table mapping LÖVE2D canonical key-name strings to `true`, owned by `Controller`
(`controller.lua`). Updated **unconditionally** on every `love.handlers.keypressed` (add key)
and `love.handlers.keyreleased` (remove key), **before any downstream handler runs**.

```lua
-- lctrl and s held simultaneously
{ ['lctrl'] = true, ['s'] = true }
```

Key names are LÖVE2D canonical (`"lctrl"`, `"rctrl"`, `"lshift"`, `"return"`, `"escape"`,
`"up"`/`"down"`/`"left"`/`"right"`, `"f1"`–`"f12"`, printable names, …). The table retains
**precise** LÖVE names (no l/r folding — folding happens only in combo serialisation, below).

### `combo_string(k, keys_pressed)`

Builds a combo string from the **triggering key** `k` and the held-key set:

- Prepend held command-modifiers in **fixed precedence** order: `ctrl`, `alt`, `shift`, `gui`.
- Append the triggering key `k`.
- Modifier names are **generic (l/r folded)**: combo uses `ctrl` (not `lctrl`/`rctrl`), etc.
- A bare key (no modifiers held) serialises to just the key name.

```lua
-- lctrl held, s triggers       -> "ctrl+s"
-- lalt and lshift held, f4     -> "alt+shift+f4"
-- escape alone                 -> "escape"
-- s alone                      -> "s"
```

> The read-only **proxy** wrapping (`__index` read-through, `__newindex` blocked) and the
> proxy being passed as the 2nd callback argument are **consumer-side** concerns introduced
> with `ProjectInputController` (M4/M5) — see `../spec.md` §1 "Ownership and passing". M1
> delivers only the live table on `Controller` and the helper.
