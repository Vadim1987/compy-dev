## Contract (this milestone)

### 1. Drop the dead profiler stub in the M1 test

`tests/input/keys_pressed_spec.lua` carries a `package.preload['controller.profiler']`
stub. The M1 review verified it is unnecessary (full suite is 685/685 without it):
`lib.profile` has no load-time LÖVE2D dependency, and the profiler's runtime path is
gated behind `if love.PROFILE`, which the test sets to `false`. Remove the preload block
and its comment.

The other two boilerplate pieces stay — they are load-bearing: `view.view` calls
`gfx.newFont()` at load (needs its stub), and `love.handlers = { }` is consumed by
`setup_callback_handlers`.

### 2. Single source of truth for the l/r modifier fold

`controller.lua`'s `combo_string` uses a local `COMBO_MODS` literal that re-declares the
`{ l*, r* }` pairs already owned by `util/key.lua` (`ctrl_k` / `alt_k` / `shift_k`). Collapse
to one definition:

- `util/key.lua` exposes the modifier groupings as `(left, right, generic)` triples,
  including a new `gui` pair (`lgui` / `rgui` / `gui`) it does not carry today.
- `combo_string` consumes the exported triples instead of its own literal; `COMBO_MODS`
  is removed.
- Fold precedence and output are **unchanged**: `ctrl`, `alt`, `shift`, `gui`, then the
  triggering key. The exported order must preserve that precedence.

## Files

- `tests/input/keys_pressed_spec.lua` — remove the `controller.profiler` preload block.
- `src/util/key.lua` — add the `gui` pair; export the modifier triples in precedence order.
- `src/controller/controller.lua` — replace the local `COMBO_MODS` with a reference to the
  exported triples.
