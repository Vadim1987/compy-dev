## Summary — the API surface at a glance

- **`compy.keys_pressed`** — live `{keyname → true}` held-key set (l/r unfolded); downstream
  as a read-only proxy. `combo_string` serialises modifier-first, l/r-folded (`"ctrl+s"`).
- **The chain** — every keyboard/text event in the project route runs the four tiers:
  `framework_handlers.<event>[combo]` → `compy.input.handlers.<event>[combo]` →
  `on_key_pressed` / `on_text_input` / `on_key_released` (default noop + debug log) → the sink
  (terminal, internally no-op when hidden). Truthy return at any tier = consumed, stop.
  **No replace-semantics anywhere**; overriding a tier never removes a lower one.
- **Widget lifecycle** — `compy.input.show(config)` / `hide()` / `configure()` / `clear()`;
  `show()` while active is a no-op unless `{force=true}`.
- **Widget outputs** — `on_text_entered(text)` (submit), `on_limit_reached(direction, scope)`,
  `validator` / `highlighter`; configurable at `show()`/`configure()` or as `compy.input`
  fields.
- **Semantic chains** — `before_submit`/`after_submit`, `before_cancel`/`after_cancel`;
  call-order, not return values; framework owns the middle step.
- **Cursor/text** — `get_cursor()` / `set_cursor(line,col)` / `set_text(text[,keep_cursor])`
  (2D, 1-based source-line coordinates).
- **Mutable boundary** — exactly the `handlers` tables + `on_*`/`before_*`/`after_*` fields;
  everything else on `compy.input` errors loudly on assignment.
- **Legacy** — text-input globals removed (D-1); native `love.*` handlers wrap as plain
  tier-3 participants (pure wrap, R7); project route connected only while `'running'`
  (keyboard/text slots only, ruling 3).

## §1 `keys_pressed` and combo serialisation

**Format.** A plain Lua table mapping LÖVE key-name strings to `true`
(`{ ['lctrl'] = true, ['s'] = true }`). Names are LÖVE canonical, **left/right unfolded**
(`lctrl` ≠ `rctrl`).

**Ownership and lifecycle.** Owned by the framework controller; updated unconditionally at
the gateway — key added on press, removed on release, **before any consumer runs** (so a
keypressed consumer sees the key present; a keyreleased consumer sees it already gone).

**Downstream passing.** Every consumer receives a **read-only proxy**: read-indexable
(`proxy['lctrl']`) and `pairs`-iterable; writes blocked (`__newindex` raises). (Round-2
stakeholder ruling — widened from iterator-only.) The proxy is the second argument of every
chain signature (§2).

**Combo serialisation.** `combo_string(trigger, keys_pressed)` prepends held command-modifiers
in fixed precedence — `ctrl`, `alt`, `shift`, `gui` — then the trigger token, `+`-joined.
Modifier names fold l/r (`"ctrl+s"`, `"alt+shift+f4"`, `"escape"`, bare `"s"`). The held set
keeps precise names; only serialisation folds. Stable and order-canonical.

**Registration normalisation.** The `handlers.<event>` tables are metatable-backed:
`__newindex` normalises assigned keys to canonical form (`['Ctrl+S']` stored as `['ctrl+s']`).
Dispatch matches via an **overloadable matcher**, default exact canonical match (O(1)); the
matcher is the marked extension seam for future glob/prefix needs.

## §2 The dispatch chain (contract)

One shape, all three keyboard/text channels, inside the active route. A tier with no
participant for the event falls through. **Truthy return at any tier = consumed → the event
travels no further (the sink included), for that event. Consuming ≠ removing: no override
ever removes a lower tier from the configuration (R13).**

**Per-channel signatures (uniform — the sink included; doc A §9 resolved):**

| Channel | Signature | Combo trigger token |
|---|---|---|
| keypressed | `(k, keys_pressed, isrepeat)` | `k` |
| textinput | `(text, keys_pressed)` | `text` (see note) |
| keyreleased | `(k, keys_pressed)` | `k` (already removed from the held set) |

**The tiers:**

1. **`framework_handlers.<event>[combo]`** — structural keys, not exposed to project space,
   non-overridable. Project route entries: `keypressed['return']` (submit chain, §5),
   `keypressed['escape']` (cancel chain, §5) — both engage only while the widget is shown;
   hidden → no participant, the combo falls through. `shift+return` is deliberately absent
   (falls to the sink → newline when `multiline`).
2. **`compy.input.handlers.<event>[combo]`** — project-registered. Three per-event sub-tables:
   `handlers.keypressed`, `handlers.keyreleased`, `handlers.textinput` (R14 — one flat table
   is forbidden). Entry signature = the channel signature; return truthy to consume.
3. **Per-event generic callback** — `compy.input.on_key_pressed(k, keys_pressed, isrepeat)`,
   `compy.input.on_text_input(text, keys_pressed)`, `compy.input.on_key_released(k, keys_pressed)`.
   **Default: noop + debug log.** Assignable (mutable boundary §7); assigning replaces the
   callback **only** — tier 4 is untouched (R13). Truthy return consumes (sink skipped for
   that event).
4. **The sink** — the widget's text editor. **Always terminal, permanently configured.**
   Visible → performs text editing (insert, backspace, cursor moves, selection, clipboard,
   Shift+Enter newline when `multiline`); boundary/submit conditions surface **only** through
   widget outputs (§4), never through return values — the sink's return has no chain meaning
   (R12). Hidden → **internal** no-op + debug log, mutates nothing (doc A §3C). There is no
   external gating wrapper.

**Channel caveats — marked in code at the dispatch site (R4):** Ctrl-chords emit **no**
`textinput`; Shift/AltGr-modified keys **do**. `keypressed` never inserts text (compy
convention, doc A §2); the only keypressed-triggered text mutations are clipboard paste and
`load_selection`.

**Textinput combos (uniformity note).** The combo tier exists on the textinput channel (R2)
keyed by `combo_string(text, keys_pressed)` — rarely useful (Ctrl-chords never reach this
channel), present for mechanism uniformity, no special rule
([`design.md`](design.md) §9 D-d).

**Repeat semantics — DEFERRED (0.1.0-m5 horizon).** Whether combo tiers fire on key-repeat is
**not ruled**; provisional leaning: fresh-only at tiers 1–2, `on_key_pressed` sees repeats
(`isrepeat` flag). Owner constraint: existing combos keep current behaviour unless explicitly
altered. Settle at implementation; carry as an in-code `DEFERRED` marker (doc A §9).

## §3 Widget lifecycle API

All under `compy.input`; the project never holds the widget object.

### `compy.input.show(config)` — activate

All fields optional:

| Field | Type | Description |
|---|---|---|
| `prompt` | string | Label beside the edit area |
| `text` | string | Initial content; cursor at end |
| `cursor` | `{line, col}` | Initial position, 1-based source-line; applied after `text` |
| `highlighter` | function | `fn(text) → highlighted_text` |
| `validator` | function | `fn(text) → ok, err_msg` (per-submit) |
| `multiline` | boolean | Shift+Enter newlines (default false) |
| `on_text_entered` | function | Widget output, §4 (config = field assignment, §4) |
| `on_limit_reached` | function | Widget output, §4 |
| `force` | boolean | Re-activate over an active session (default false) |

`show()` while already active = **no-op + warning** (state untouched, no cancel chain).
`force = true` reconfigures in-place (content replaced iff `text` given), still no cancel
chain. Fresh activation with no `text` starts empty. Sets `love.state.user_input` (mechanism,
non-binding).

### `compy.input.hide()` — deactivate silently

No cancel chain. Content preserved for the next `show()` without `text`. Programmatic
lifecycle path; the user-facing dismiss is Escape (§5).

### `compy.input.configure(config)` — live update

Same fields as `show()` minus `force`. Only provided fields change. Live-updatable: `prompt`,
`highlighter`, `validator`, the widget-output callbacks. `text`/`cursor` are accepted but
have no effect on an active session (use `set_text`/`set_cursor` §6, or `clear()` + `show()`).
Safe when hidden — takes effect on next `show()`.

### `compy.input.clear()` — reset content

Clears content, cursor to start, no callback fires. No-op (+ warn) when hidden.

## §4 Widget outputs

Routing **out of** the widget (R1) — not chain tiers; not bound by chain signatures; never
reported via chain return values (R12). Each is both a `show()`/`configure()` config key and
an assignable `compy.input` field — one underlying slot, two ergonomics
([`design.md`](design.md) §9 D-b).

- **`on_text_entered(text)`** — fires at submit (text assembled + Enter), invoked by the
  framework's submit step (§5) with the full assembled text. Default: noop + debug log.
  *Never* the per-character callback (that is the chain's `on_text_input`, §2).
- **`on_limit_reached(direction, scope)`** — cursor attempted to move past a boundary.
  `direction`: `'up' | 'down' | 'left' | 'right'`; `scope`: `'input'` (whole input) |
  `'line'` (current line) — D-5, both scopes; single-line inputs collapse the two. Always
  observational; return value ignored.
- **`validator`** — `fn(text) → ok, err_msg`, consulted by the submit step (§5).
- **`highlighter`** — `fn(text) → highlighted_text`, applied as the user types.

## §5 Submit and cancel — framework tier + semantic chains

Semantic chains order by **call position**, not return values; the framework owns the middle
step; hooks cannot suppress it. All four hooks default to noop + debug log.

**Scope note (binding).** What is uniform across every present and future chain adopter is
the submit **shape**: the widget never owns submit; the owning route's tier-1 handler does,
wrapped in the D-4 hook chain. The middle-step **content** below — validate → deliver →
**deactivate** — is the **project route's policy**, not a widget property
([`design.md`](design.md) §3). Console/editor, when they migrate, mint their own middle steps
and keep their widgets shown: truly persistent sessions, no re-show involved. A persistent
project-route option, if ever needed, is an additive extension (reserved, R9-adjacent, not
built).

**Submit** (`framework_handlers.keypressed['return']`, widget shown):

```
before_submit(keys_pressed)
→ submit (framework): validator(text) →
    reject: error display, input locked until acknowledged; nothing below fires
    accept: on_text_entered(text) → widget deactivates (auto-close on submit)
→ after_submit(text)
```

A `before_submit` veto return is a **reserved future extension** (R9) — ignored today, the
design must not preclude it; blocking bad input at submit is the validator's job (FR-1).

**Continuous-session idiom** (balloons-style: submit, clear, re-prompt, keep receiving):
deactivate-on-submit is **unconditional** — there is deliberately no keep-open mode (a
keep-open flag is `oneshot` reborn with the polarity flipped). A project that wants the next
prompt re-activates from its hook:

```lua
after_submit = function(text)
  compy.input.show{ prompt = next_prompt(text) }
end
```

Fresh activation without `text` starts empty, so the "clear" comes free. Callbacks and
`handlers.*` persist across deactivation (configuration is permanent — only project stop
resets, §8), so the re-show is this one line, not a re-setup. The re-activation runs inside
the same submit sequence, before the frame draws — no visible gap. NFR-1 holds: `show`/`hide`
are state flips on the boot-provisioned widget.

**Mechanism note — the old `push('userinput')`, dissolved.** Today's `oneshot` submit fills
the reftable synchronously, then pushes a custom `'userinput'` LÖVE event
(`userInputModel.lua` evaluate path); `handlers.userinput` (`controller.lua`) nulls
`love.state.user_input` on the **next** event dispatch. Its two jobs: (1) signal
"value ready" to the per-frame polling loop — dissolves with polling itself (§9;
`on_text_entered` is the push-notification replacement); (2) defer overlay teardown out of
the widget's own `keypressed` call stack — absorbed by the deactivate step. Whether an
implementation deactivates synchronously or via a deferred event is mechanism, non-binding
(ruling 5); the contract only fixes the observable order (`on_text_entered` sees the session
still active; `after_submit` runs with the widget deactivated — or re-activated by the hook
itself, above).

**Cancel** (`framework_handlers.keypressed['escape']`, widget shown):

```
before_cancel(keys_pressed)
→ cancel (framework): content cleared → widget hidden
→ after_cancel()
```

This fixes the known limitation: Escape now genuinely dismisses. `hide()` (§3) fires **no**
cancel chain — cancel is the user-facing path only.

## §6 Cursor and text control (FR-8/9/10 — the M7 surface)

D-8 contract: 2D `(line, col)`, 1-based **source-line** coordinates (not wrapped/apparent).

- **`compy.input.get_cursor()`** → `line, col`; `nil` when hidden.
- **`compy.input.set_cursor(line, col)`** — clamped to valid range; no-op (+ warn) when hidden.
- **`compy.input.set_text(text [, keep_cursor])`** — replaces content of the active session
  (the live-write surface; the explicit exception to `configure()`'s text-immutability).
  `keep_cursor` truthy preserves the position; else cursor to end. No-op (+ warn) when hidden.

**Consumers under auto-close-at-submit** (Gate-2 round-1): a session spans the whole
composition, so this surface is live the entire time the user is typing. Validator-reject
flows jump the cursor to the error position (today's evaluate-fail path in
`userInputModel.lua` does exactly this); `on_limit_reached` → `set_text`/`set_cursor` wiring
implements history-navigation-style flows (the console proof case, available to any project);
draft restore rides `show{text=…, cursor=…}`; console/editor migration is the heaviest future
consumer (the editor's Escape load-selection is `set_text`). `highlighter` likewise runs live
for the whole session — `input_code`-style composition is its flagship case.

## §7 The mutable/immutable boundary (R3)

**Project-mutable — exactly:**

| Surface | Kind |
|---|---|
| `compy.input.handlers.keypressed` / `.keyreleased` / `.textinput` | writable tables (normalising, §1) |
| `compy.input.on_key_pressed` / `on_text_input` / `on_key_released` | chain tier-3 callbacks |
| `compy.input.on_text_entered` / `on_limit_reached` | widget outputs (§4) |
| `compy.input.before_submit` / `after_submit` / `before_cancel` / `after_cancel` | semantic-chain hooks (§5) |

**Everything else on `compy.input`** (`show`, `hide`, `configure`, `clear`, `get_cursor`,
`set_cursor`, `set_text`, the `handlers` container itself) is callable API, **protected
against assignment — errors loudly** (C2: never a silent swallow). Naming tweakable
post-implementation; the boundary is not.

## §8 Route connection lifecycle

- **Connect:** the project route occupies the **keyboard/text** slots (`keypressed`,
  `textinput`, `keyreleased`) when `app_state` enters `'running'` — and only then (ruling 3).
  When a non-blocking `main.lua` returns (no `update`/`draw` hooked) the state drops to
  `'project_open'` and the keyboard/text slots restore to the console route. **Pointer slots
  are NOT part of this disconnect** — pointer natives stay hooked until project stop
  (pen-and-paper projects like `sapper` remain clickable in `'project_open'`;
  [`design.md`](design.md) §4). Do not unify pointer disconnection in.
- **Stop:** all slots restore to framework defaults; `handlers.*` tables and every mutable
  field (§7) reset to defaults; no project participant stays wired (doc A §6.4). Widget shown
  at stop → silent hide, no cancel chain. **Teardown invariant:** no callback, combo entry, or
  widget configuration survives the project that installed it — the next project (or route)
  starts from framework defaults. Route switches short of stop don't reset, but a disconnected
  route's participants receive nothing (connect rule above), and a widget whose owning route is
  inactive goes unhonoured (the `inspect` bullet is the model case) — so stale configuration
  can never act outside its creator's window.
- **`inspect` (R11):** the console route active, bound over the project environment; project
  route disconnected; the project widget unhonoured (owning route inactive). No special rules.
- **Native handlers = pure wrap (R7):** natives (`love.keypressed`/`textinput`/`keyreleased`)
  a project defines are captured at load and installed as the **initial values of the
  corresponding tier-3 callbacks** (`on_key_pressed`/`on_text_input`/`on_key_released`) —
  plain participants, no widget-aware gating. A native returning nothing falls through to the
  sink like any tier-3 falsey return; a project assigning the field replaces the wrapped
  native like any callback (tier 4 untouched, R13). Consequence: natives see events while the
  widget is shown; turtle/maze migrate under the SR1 break mandate (rides the dispatch-chain
  slice — [`design.md`](design.md) §5).

## §9 Legacy API removal (D-1 — unchanged)

The legacy text-input globals are **removed**, not wrapped — no shim, no flag; the
reftable/`is_empty()` polling idiom goes with them:

| Removed | Replacement |
|---|---|
| `user_input()` | none — submit observed via `on_text_entered(text)` (+ `after_submit`) |
| `input_text(prompt, init)` | `compy.input.show{ prompt = prompt, text = init, validator = <text-eval>, on_text_entered = fn }` |
| `input_code(prompt, init)` | same + `highlighter`/`validator` for Lua |
| `validated_input(fn, prompt)` | `compy.input.show{ prompt = prompt, validator = fn, on_text_entered = fn }` |
| `write_to_input(content)` | `compy.input.set_text(content)` |

The break is bounded to text fields (SR1); native keyboard handling keeps working (§8 pure
wrap — with the turtle/maze exception ruled R7). Example migration lands with the
legacy-removal slice; **turtle/maze specifically ride the dispatch-chain slice** (§8).

## §10 Edge cases

- **`show()` while active** — §3: no-op + warn; `force` reconfigures in-place; never a cancel
  chain.
- **Project stops while widget shown** — silent hide; callbacks reset; no observable teardown
  event (the project is gone).
- **Validator rejects at submit** — error display, input locked until acknowledged
  (Enter/Space/arrows), then editable again; `before_submit` has fired; `on_text_entered` and
  `after_submit` have not; session stays active until corrected+resubmitted or Escaped.
- **Event with no participant anywhere** (hidden widget, no handlers, default callbacks) —
  falls through every tier to the hidden sink's internal no-op; the debug log is the trace
  (C2: visible, never silent).
