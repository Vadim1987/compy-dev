# Workflow — the session OS

_Generated by LLM(Claude Opus 4.8): 2026-06-20 (v0.0.10-min, token-optimized cut); 

> **MIN BUILD.** This is the token-optimized cut of 'brainlab v0.0.10': critical-path directives only.

A chat runs **boot → track → gates → wrap**, one numbered prompt at a time. 

## Summary

- **Serial-prompt cycle** — advance one `sessionNN/prompt.md` at a time; each prompt is the task and a
  handoff.
- **Boot** the highest-numbered prompt; it is **immutable** — never edit a booted or predecessor prompt.
- **Re-entrance guardrail** — read boot state from which artifacts exist (`track.md`/`report.md`).
- **Track** — always-on scratchpad, appended on a per-turn "worthy" check; **kept always**.
- **Gates** — iterate with the human until **explicitly approved**; never wrap early.
- **Wrap** — distil the track into report + successor prompt; handover format depends on task nature.

## 1. The serial-prompt cycle

1. Read the highest-numbered `sessions/sessionNN/prompt.md` — current task + handoff (points to
   the predecessor's `report.md`).
2. **Determine whether the prompt specifies a task.** If yes, proceed. If it is a placeholder deferring
   to the human, ask for instructions and act on them.
3. Run the **re-entrance guardrail** (§2). Do the task. **Iterate until explicitly approved** (§4).
4. Only once complete **and approved**, **wrap** (§5).

**Immutable-prompt rule.** Never edit the booted prompt or any predecessor. Mid-session instructions go
to the running `track.md` and are distilled at wrap-up.

## 2. Re-entrance guardrail — read boot status from the artifacts

| On disk | State | Action |
|---|---|---|
| neither `track.md` nor `report.md` | **fresh start** | begin the task, open the track (§3) |
| `track.md`, no `report.md` | **interrupted before wrap** | absorb the track, reconstruct where it stopped, tell the human what's outstanding, ask resume / redo / redirect — do **not** silently restart |
| `report.md` present | **likely wrapped** | confirm via expected artifacts; if complete, don't redo — ask whether continuation or new prompt is intended |

When unsure, ask.

## 3. The running track (`sessionNN/track.md`)

- **Trigger = "worthy", re-checked every turn.** If something important accumulated since the last
  entry — **project** (fact, decision, instruction, pivot) or **behavioural** (a notable move in how the
  human thinks/frames/doubts/decides) — append a short, loosely-anchored note; else write nothing.
- Keep entries raw and telegraphic.
- The track is the on-disk trace before wrap-up; 
- **Tracks are KEPT, always** — distilled at wrap-up, never destroyed.
- **Sibling: materialization.** Valuable chat content (substantive answers/insights, ad-hoc human
  attestations) is separately persisted to disk as produced (typically under notes/ subdir) — see
  [`rules/materialization.md`](rules/materialization.md).

## 4. Gates — the approval discipline

Do the task and **iterate until explicitly approved** before considering it done. Do not write the
report or successor prompt early; do not skip the gate. Contradictions/under-specifications are decided
**with the human**, never papered over.

## 5. Wrap — distil the track, choose the handover format

Only after complete **and approved**, distil the track, then retire it (raw track kept per §3):

- **project / task essentials → the report** (`sessionNN/report.md`): outcome, reasons, non-obvious
  points — briefly. Don't retell every step.
- **major pivots / milestones → one line in the successor prompt's carryover** — contextual.

Then write the **successor prompt** (`sessionNN+1/prompt.md`): explain the taskflow, summarize the
report **one abstraction level higher**, **reference the report file** (don't inline), and frame "Your
task" by the **completed task's nature**:

| Completed task | Successor "Your task" |
|---|---|
| **Cognitive-heavy** (judgment exercised) | a **revalidation** task — read commissioning prompt + report, work [`rules/revalidation.md`](rules/revalidation.md) |
| **Revalidation task** | a wait-for-human placeholder |
| **Non-cognitive-heavy** (reorg, housekeeping, rule/prompt authoring) | a wait-for-human placeholder |

**Side-track handover rule.** If the task was a detour, the successor prompt must recite — verbatim or
by reference — the last substantive task outcome, so the primary thread stays active context.

## 6. Operating constraints

- **Editing files is allowed.** Local workspace ops (`bash`, `sed`, `grep`, `awk`, …) are pre-approved —
  don't ask.
- **Reading public internet content is allowed.**
- **Do not send workspace content to the outside world** beyond the agent API.
