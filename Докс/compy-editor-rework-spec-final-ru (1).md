# ТЗ: переделка редактора Compy — финальная версия

Статус: утверждено по поведению.
Оценки объёма — отдельным документом.

Документ состоит из продуктовой части (разделы 1–4) и технической
(разделы 5–9). Техническая часть следует из продуктовой.

---

## 1. Общие положения

**1.1. Цель и рамка.** Блочный редактор — в первую очередь
педагогическая идея: ограничение, которое подталкивает ребёнка к
структурированному мышлению. Цель переделки — не приблизить его
к обычному редактору (повторять vim или nano бессмысленно: мы
потеряли бы уникальный дидактический инструмент, получив плохой
обычный редактор), а сделать работу внутри блочной рамки
предсказуемой и комфортной, с привычными горячими клавишами
(конвенции Windows/Linux). Целевая аудитория — дети:
предсказуемость поведения приоритетнее плотности функций.

**1.2. Блочная модель.** Единица сохранения — блок (законченная
конструкция верхнего уровня); автоформатирование при принятии
блока остаётся.

**1.3. Принятые решения:**

- Лимит размера блока — **14 строк** (высота полосы ввода).
  Открытый блок всегда виден целиком; прокрутки внутри блока не
  существует ни при каких обстоятельствах.
- Блок сверх лимита не сохраняется: явное видимое сообщение
  вида «Too many lines in a block. Remove N lines to save or
  press Shift+Esc to cancel». Блоки крупнее лимита из внешних
  файлов открываются для просмотра и правки; сохранение — после
  приведения к лимиту либо разрезание при принятии.
- Файл, который не удалось разобрать, открывается **только для
  чтения**, как сейчас. Построчный режим редактирования не
  вводится (осознанное решение рамки 1.1); починка такого файла
  выполняется вне устройства (карточка + обычный компьютер).
- Правая кнопка мыши устройства генерирует Esc — **временное
  свойство**, до отвязки на уровне системы; требования к Esc
  (п. 2.3) проектируются под него, но фиксируются как
  самостоятельные.
- Изменения применяются в память; на диск файл записывается
  явными действиями (п. 2.6).

## 2. Целевое поведение

### 2.1. Режимы

- **Навигация** — перемещение по файлу, операции над блоками.
  Ввод текста не изменяет файл; набор печатных символов
  открывает строку поиска и ищет по мере набора.
- **Редактирование** — открыт ровно один блок; весь ввод
  направляется в него.

Режимы переноса блоков (Ctrl+M) и поиска (Ctrl+F) — подрежимы
навигации. Текущий режим виден постоянно: индикатор в строке
статуса и цвет рамки активного блока.

### 2.2. Навигация: строки, не блоки

Выделение в навигации перемещается **по строкам**: стрелки
вверх/вниз ходят на одну строку (переход по крупному блоку не
вызывает скачка и потери ориентации). Enter открывает блок,
которому принадлежит выделенная строка, с курсором на этой
строке.

Переход по блокам — Ctrl+↑/↓ (конвенция «по абзацам»):

- Ctrl+↓ — на первую строку следующего блока;
- Ctrl+↑ — на первую строку текущего блока, если выделена не
  она; иначе — на первую строку предыдущего блока.

Прокрутка без перемещения выделения: Alt+↑/↓ — на строку,
PageUp/PageDown — на страницу.

### 2.3. Клавиша Esc

Одиночный Esc безопасен в любом контексте (см. 1.3 про ПКМ).

| Контекст | Esc | Shift+Esc |
|---|---|---|
| Навигация | нет действия | выход из редактора; при несохранённых изменениях — предложение сохранить (сохранить / не сохранять / остаться) |
| Редактирование | нет действия | отменить правки блока, вернуться в навигацию к этому блоку |
| Перенос блоков | нет действия | отменить перенос |
| Поиск | нет действия | отменить поиск |

Esc не открывает блок ни при каких условиях. Семантика
Shift+Esc едина: выход / отмена на уровень вверх. Shift+Esc —
именно выход, не «выход без сохранения»: потерять изменения
можно только явным ответом «не сохранять».

### 2.4. Переходы из открытого блока

Внутри открытого блока стрелки перемещают курсор по строкам
блока. Требования на любой способ покинуть блок (стрелка за
край, Ctrl+↑/↓, переход из поиска, закрытие файла):

1. Блок не изменялся — переход без побочных действий.
2. Изменялся — проверка корректности и **принятие в память**
   (автоформат, перестроение блоков; записи на диск нет).
3. Некорректен — переход не выполняется: короткий звук (уважая
   выключенный звук устройства), красная рамка, сообщение о
   причине, курсор к месту ошибки.
4. Принятие при переходе стрелкой открывает соседний блок:
   вниз — с курсором на его первой строке, вверх — на
   последней. Экран прокручивается к открывшемуся блоку;
   принятие без перехода возвращает экран к текущему блоку.

Прокрутка из открытого блока (Alt+↑/↓, PageUp/PageDown) —
просмотр контекста: блок не меняется, ввод текста возвращает
экран к блоку.

### 2.5. Сообщения об ошибках

В версии 1.0 показываются сообщения парсера как есть, в строке
статуса, до первого исправляющего нажатия. Перевод сообщений на
понятный детям язык — отдельная UX-работа всей командой, вне
рамок данного ТЗ.

### 2.6. Сохранение

- Принятие блока (Enter, переход) применяет изменения к файлу
  **в памяти**.
- Запись на диск: Ctrl+S (явное сохранение с индикацией) и
  закрытие файла Ctrl+W (записывает и закрывает).
- Shift+Esc в навигации — выход; при несохранённых изменениях
  редактор предлагает сохранить (сохранить / не сохранять /
  остаться).
- Признак несохранённых изменений виден постоянно (маркер в
  строке статуса).

### 2.7. Горячие клавиши

Конфликты текущей раскладки с конвенциями, из-за которых
пересмотр обязателен: Ctrl+Y (сейчас удаление блока, в
конвенциях — повтор), Ctrl+S (сейчас закрытие, в конвенциях —
сохранение), Ctrl+O (сейчас переход в подключённый файл, в
конвенциях — открытие).

| Комбинация | Навигация | Редактирование |
|---|---|---|
| ↑/↓ | выделение на строку | курсор по строкам блока |
| Ctrl+↑/↓ | переход по блокам (п. 2.2) | принятие + переход по блокам |
| Alt+↑/↓ | прокрутка на строку | прокрутка на строку (контекст) |
| Ctrl+Alt+↑/↓ | перенести блок | перенести строку вверх/вниз |
| PageUp/Down | прокрутка на страницу | прокрутка (контекст) |
| Enter | открыть блок (курсор на выделенной строке) | перенос строки |
| Ctrl+Enter | новый пустой блок под выделенным, открыть | принять блок, перейти в навигацию |
| Shift+Esc | выход (предложение сохранить) | отменить правки блока |
| Ctrl+C / Ctrl+Insert | копировать блок | копировать выделенный текст |
| Ctrl+X / Shift+Delete | вырезать блок | вырезать выделенный текст |
| Ctrl+V / Shift+Insert | вставить как блок(и) под выделенным | вставить текст |
| Ctrl+Delete | удалить блок | — |
| Ctrl+A | — | выделить весь блок |
| Ctrl+←/→ | — | переход по словам |
| Shift+стрелки | — | выделение текста |
| Home / End | первая / последняя строка файла | начало / конец строки |
| Ctrl+S | записать на диск (индикация) | записать на диск |
| Ctrl+W | записать и закрыть файл | — |
| Ctrl+F | поиск (также открывается набором текста) | — |
| Ctrl+M | режим переноса блоков | — |
| F12 | переход в подключённый файл | — |

Примечания к раскладке:

- Новый блок — Ctrl+Enter в навигации (Insert отклонён:
  традиционно это переключение insert/overwrite).
- Ctrl+M в терминалах эквивалентен Enter (посылает CR); в
  редакторе устройства конфликт не воспроизводится, сочетание
  сохранено; при обнаружении проблем на устройстве заменяется.
- Undo/Redo (Ctrl+Z / Ctrl+Y) — предусмотрены раскладкой,
  в версии 1.0 отключены (п. 2.8).

### 2.8. Отмена действий

Полноценный Undo/Redo (двухуровневый: текст в блоке и операции
над блоками) согласован принципиально и реализуется отдельным
этапом **после версии 1.0**. В версии 1.0 защита от потери —
уровень файла: изменения не пишутся на диск автоматически;
выйти, не записав, можно ответом «не сохранять» на предложение
при выходе; Shift+Esc в редактировании откатывает блок и
возвращает к нему.

### 2.9. Мышь

Реализуется этапом 3. Целевое поведение: щелчок — выделение
строки; двойной щелчок — открыть блок; щелчок в другой блок из
редактирования — по правилам п. 2.4; щелчок внутри открытого
блока — установка курсора.

## 3. Порядок работ

1. **Этап 1 — режимы и поведение**: разделение режимов,
   Esc-семантика с предложением сохранить, строчная навигация с
   Ctrl-переходами по блокам, единый порядок выхода из блока,
   принятие в память + явная запись, лимит 14, индикация режима
   и несохранённых изменений, обратная связь.
2. **Этап 2 — горячие клавиши**: раскладка п. 2.7 поверх новой
   схемы обработки ввода; подавление символов при комбинациях;
   прокрутка Alt/страницами. Перед началом — проверка на
   устройстве.
3. **Этап 3 — мышь.**

Вне версии 1.0: Undo/Redo; словарь детских сообщений об ошибках
(отдельная командная UX-работа).

## 5. Текущая реализация (справочно)

Ссылки на код — dev @ 7728158; учтён завершённый этап работ по
разделению режимов (ветка feat/editor-nav-editing).

Исходная реализация совмещала навигацию и правку в одном режиме
`edit` с различением по косвенным признакам; выполненный этап
ввёл явные режимы `nav`/`editing`, единый порядок выхода из
блока (dirty-check → валидация → принятие/отказ) и семантику
Esc/Shift+Esc. Данная версия ТЗ дополнительно меняет:

- лимит блока: 14 (закрывает расхождение input_max = 14 против
  проверки на 16 — в пользу 14; правка одной точки
  `get_max_size`);
- единицу выделения навигации (блок → строка) с переходами по
  блокам на Ctrl+↑/↓;
- модель персистентности: принятие пишет в память, на диск —
  Ctrl+S/Ctrl+W; при выходе с несохранённым — предложение
  сохранить;
- ввод текста в навигации: открытие поиска с автопоиском вместо
  сочинения нового блока;
- Undo переносится за 1.0.

Конвейер принятия (автоформат → перестроение → проверка
размера → замена с пересчётом позиций) сохраняется; меняется
адресат записи (память вместо диска) и точки записи.

## 6. Модель состояний и переходы

Состояния `nav`/`editing`, подрежимы `reorder`/`search` из
`nav`. Выделение навигации — строка (модель: индекс строки
файла; принадлежность блоку вычисляется по существующим
позициям блоков). Открытие блока ставит курсор на выделенную
строку.

Единый порядок выхода из блока — как реализовано, с двумя
изменениями: принятие не пишет на диск; после принятия
переходом экран прокручивается к открывшемуся блоку, после
принятия на месте — к текущему.

Грязность файла (принятые, но не записанные изменения) — флаг
буфера; питает индикацию, предложение сохранить при выходе и
запись Ctrl+S/Ctrl+W.

## 7. Реализация горячих клавиш

Диспетчеризация поверх схемы обработки ввода #77 (реестр
комбо-строк с сериализацией вида "ctrl+s", таблица нажатых
клавиш, признак повтора); редактор — второй потребитель схемы,
отдельный механизм не строится. Подавление символов комбинаций
структурно (textinput при нажатом Ctrl/Alt игнорируется).
Повторы разрешены движению (стрелки, прокрутка), запрещены
командам.

## 8. Координация с input-слоем и проверка на устройстве

Границы прежние: свободно — всё после получения ввода; по
согласованию — внутренности userInputController и вызов его
обработчиков; принимается внешнее — механизм диспетчеризации
(#77). Дополнительная точка согласования: диалог предложения
сохранить, если он строится на input-виджете.

Проверка на устройстве до этапа 2: попадание символов
комбинаций в текст платформенного поля ввода; порядок
textinput/keypressed на платформенном пути; символы повторов
при удержании; подтверждение уровня привязки ПКМ→Esc (и
фиксация её временности).

## 9. Критерии приёмки

1. ПКМ и одиночный Esc в любом состоянии не выполняют действий.
2. Стрелки в навигации ходят по строкам; Ctrl+↑/↓ — по блокам
   по правилам п. 2.2; Enter открывает блок с курсором на
   выделенной строке.
3. Выход стрелкой за край открытого блока: корректный
   изменённый блок принят в память, открыт соседний с курсором
   на ближней строке, экран прокручен к нему; некорректный —
   звук, рамка, сообщение, блок остаётся. Прокрутки внутри
   блока не существует.
4. Неизменённый блок при переходе не переформатируется.
5. Принятие не записывает на диск; Ctrl+S записывает; Ctrl+W
   записывает и закрывает; Shift+Esc при несохранённых
   изменениях предлагает сохранить, потеря возможна только
   ответом «не сохранять».
6. Блок из 15+ строк не сохраняется: видимое сообщение с
   указанием превышения; Shift+Esc отменяет.
7. Набор текста в навигации открывает поиск и ищет по мере
   набора; файл не меняется.
8. Файл с ошибкой разбора открывается только для чтения.
9. Текущий режим и признак несохранённых изменений видны
   постоянно.
10. Shift+Esc из редактирования возвращает исходный текст блока
    и оставляет выделение на нём.
