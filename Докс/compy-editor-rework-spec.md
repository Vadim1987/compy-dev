## 1. Общие положения

**1.1. Цель.** Во встроенном редакторе должно быть комфортно
работать с кодом; привычные горячие клавиши (конвенции
Windows/Linux) должны работать. Целевая аудитория — дети,
изучающие программирование: предсказуемость поведения и понятность
ошибок приоритетнее плотности функций.

**1.2. Рамка.** Блочная модель редактора сохраняется и дорабатывается:
единица работы — блок (законченная конструкция верхнего уровня),

## 2. Целевое поведение

### 2.1. Режимы

Вводятся два явных режима вместо текущего совмещённого:

- **Навигация** — перемещение по блокам, выделение, операции над
  блоками (копирование, вырезание, удаление, перенос). Ввод текста
  в этом режиме не изменяет содержимое файла.
  
- > DS: Непонятно, о каком вводе текста речь. В смысле — нажатие клавиш? Да, работают только шорткаты. При непосредственном вводе текста можно открывать поисковую строку с автоматическим поиском набираемого
  >
  > Ещё важно: перемещение по блокам приводит к резкому перескакиванию и потере ориентации, если блоки большие. Я считаю, что стрелки должны переходить по строчкам, а не по блокам. При этом, если мы нажимаем Enter, чтобы открыть редактирование, можно ставить курсор сразу на ту строчку, которая была выделена в навигации.
  >
  > Для перехода между блоками можно использовать Ctrl-Up/Down: это стандартный шорткат для перехода между параграфами. Ctrl+Down: всегда переносит курсор в начало следующего блока (т.е. выделает его первую строчку). Ctrl+Up: если была выделена первая строчка блока, отматывает до первой строчки предыдущего блока, а если была выделена любая другая строчка блока, переходит на первую строчку текущего блока.

- **Редактирование** — открыт ровно один блок; весь ввод направляется
  в него; операции над другими блоками недоступны до выхода.

Существующие режимы переноса блоков (Ctrl+M) и поиска (Ctrl+F)
сохраняются как подрежимы навигации.

> DS: Ctrl+M — стандартное сочетание в консолях?

Текущий режим должен быть виден постоянно: индикатор в строке
статуса и цвет рамки активного блока.

### 2.2. Клавиша Esc

Правая кнопка мыши устройства генерирует Esc, поэтому одиночный Esc
обязан быть безопасным в любом контексте.

| Контекст | Esc | Shift+Esc |
|---|---|---|
| Навигация | нет действия | закрыть редактор (выход в консоль) |
| Редактирование | нет действия | отменить правки блока (восстановить исходный текст), перейти в навигацию |
| Перенос блоков | нет действия | отменить перенос |
| Поиск | нет действия | отменить поиск |

- Esc не открывает блок ни при каких условиях. Открытие блока —
  Enter на выделенном блоке в режиме навигации.
- Семантика Shift+Esc едина во всех контекстах: отмена / выход на
  уровень вверх.

### 2.3. Переходы между блоками

Требования к любому способу покинуть редактируемый блок (стрелка за
край, переход к началу/концу файла, переход из поиска, щелчок мыши
по другому блоку, закрытие файла):

1. Если блок не изменялся — переход выполняется без побочных
   действий: без переформатирования, без записи на диск.

2. Если блок изменялся — выполняется проверка корректности и
   сохранение.

   > DS: Важно! Сохранение не на диск, а только в памяти. Мы всё ещё можем отменить **все** изменения в файле, нажав Shift+Esc в режиме навигации. При этом, если изменения были, надо дополнительно запросить подтверждение.

3. Если блок некорректен — переход не выполняется. Обратная связь:
   короткий звуковой сигнал, красная рамка блока, текстовое сообщение
   о причине; курсор устанавливается к месту ошибки.

4. При переходе стрелкой за край открывается соседний блок.
   Состояние «выделение переместилось, открыт прежний блок»
   исключается.

Прокрутка страницами (PageUp/PageDown) в режиме редактирования
допускается как просмотр контекста: редактируемый блок при этом не
меняется; ввод текста возвращает экран к редактируемому блоку.

### 2.5. Файлы с ошибками синтаксиса

Текущее поведение: файл, который не удалось разобрать, открывается
только для чтения; исправление в редакторе невозможно.

Целевое поведение: такой файл открывается в построчном режиме с
уведомлением «в файле ошибка — построчный режим»; ошибка показывается
по правилам п. 2.4 с указанием позиции. После исправления и
успешного разбора при сохранении редактор возвращается к блочному
режиму.

> DS: Построчный режим вообще должен быть доступен как отдельная фича, чтобы его можно было вручную включить для любого файла. Файл может парситься, но блоки там могут быть неверные. У нас должна быть возможность вручную переместить всякое между блоками и т.п.

### 2.7. Отмена действий

Отмена в текущей реализации отсутствует. При автосохранении каждого
принятия блока и принятии по переходу (п. 2.3) её отсутствие означает
необратимость случайных действий, что для целевой аудитории
неприемлемо.

Требования:

- Ctrl+Z — отмена, Ctrl+Y — повтор.

- Два уровня: текстовый (правки внутри открытого блока) и блочный
  (принятие, удаление, перенос, вставка блоков). Отмена принятия
  восстанавливает и текст, и предыдущую сохранённую версию.
  
- Принятие, выполненное переходом (п. 2.3), отменяемо наравне с
  явным.

- Глубина — не менее текущего сеанса по активному файлу.

## 5. Текущая реализация (справочно)

Ссылки на код — dev @ 1a0261c.

Режим `edit` совмещает навигацию и правку в одном диспетчере
`_normal_mode_keys` (editorController.lua:507): цепочка обработчиков
submit → load → delete → navigate → clear; не перехваченные нажатия
передаются в текстовый виджет (:803). Различение выполняется по
косвенным признакам:

- пустота поля ввода: Ctrl+C/X/Y действуют на блок только при пустом
  поле; при непустом та же комбинация уходит в виджет (собственная
  обработка выделения — userInputController:313);
- положение курсора: стрелки на краю поля ввода переключаются на
  перемещение выделения буфера (:709–762) — источник расхождения
  курсоров.

Загрузка блока: Esc → `load_selection()` (:716–726); Shift+Esc —
дозагрузка. Собственного поля у редактора нет — используется
userInput-виджет. Конвейер принятия `_handle_submit` (:321):
автоформат → повторное разбиение → сохранение/вставка пустых
разделителей → проверка размера (`bufv:get_max_size()` = 16;
фиксируется как норма) → замена/вставка с пересчётом позиций →
автосохранение.

Защита `loaded` (bufferModel:516–545): принятие при расхождении
выделения и загруженного блока не перезаписывает чужой блок. В
целевой модели свойство сохраняется; необходимость в отдельном
механизме отпадает — в редактировании открыт ровно один блок.

## 6. Модель состояний и переходы

Состояния `nav` и `editing`; `reorder` и `search` — подрежимы `nav`.
Используется существующий механизм режимов (`set_mode`); построение
нового не требуется. Индикация — по п. 2.1.

Единый порядок выхода из редактируемого блока (реализация п. 2.3):

1. проверка изменённости; не изменялся — выход без побочных действий;
2. изменялся — проверка корректности: разбор, лимит 16 строк,
   ограничение длины строки 64 (валидатор LuaEditorEval);
3. некорректен — отказ: звук (util.audio), состояние рамки `invalid`
   в bufferView, сообщение по словарю (п. 2.4), курсор к позиции из
   парсера;
4. корректен — принятие существующим конвейером `_handle_submit`.

Порядок един для всех путей выхода, перечисленных в п. 2.3.

## 7. Реализация горячих клавиш и отмены

- Диспетчеризация — поверх схемы обработки ввода, выпускаемой для
  проектов (реестр комбинаций → обработчик → признак остановки →
  передача далее). Редактор — второй потребитель схемы; отдельный
  параллельный механизм не создаётся. Форма интеграции определяется
  после выпуска схемы.
- Комбинация определяется как клавиша плюс множество модификаторов;
  определение не зависит от порядка событий (порядок не гарантирован
  фреймворком LÖVE). Источник — дополнительные параметры
  keypressed/textinput новой схемы: таблица нажатых клавиш, признак
  повтора.
- Подавление символов при комбинациях выполняется структурно.
  Текущее состояние: фильтр только на Ctrl+Shift
  (editorController:294); платформенный textinput не фильтрует
  (userInputController:392). Обе точки закрываются новой схемой:
  textinput при нажатом Ctrl/Alt игнорируется.
- Повторы клавиш: разрешены навигации (удержание стрелки), запрещены
  командам (удержание Ctrl+V не вставляет многократно). Признак —
  isrepeat новой схемы.

Отмена (п. 2.7): выбор механизма (история команд либо снимки
состояния буфера) — решение реализации. Ограничения: Lua 5.1;
расход памяти соразмерен устройству — глубина сеанса не должна
приводить к неограниченному росту.

## 8. Файлы с ошибками — реализация

Текущее: неуспешное разбиение при открытии → `readonly = true`.
Целевое: переход на построчное представление (существующий механизм
VisibleContent для plain-файлов) с уведомлением; при успешном разборе
на сохранении — возврат к блочному представлению (повторное
разбиение). Поведение монстр-блоков не меняется.

## 9. Координация с input-слоем и проверка на устройстве

Границы (согласованы с владельцем input-слоя):

- Без согласования: логика после получения ввода — буферы, блоки,
  курсоры, состояния, порядок выхода из блока; подключаемые
  валидаторы.
- По согласованию: внутренности userInputController; способ вызова
  его обработчиков; нетривиальные манипуляции love-callbacks.
- Принимается внешнее: механизм диспетчеризации комбинаций (схема
  проектов). Сведение моделей input-слоя и редактора — совместная
  задача этапа интеграции после выпуска схемы.

Проверка на устройстве до этапа 2:

1. Попадание символов комбинаций в текст платформенного поля ввода
   (Ctrl+V, Alt+буква) — фильтры на одиночный Ctrl/Alt отсутствуют,
   адреса в разделе 7.
2. Порядок textinput/keypressed на платформенном пути (каталог
   особенностей ввода составлен для пути «IDE → проект»).
3. Символы повторов при удержании клавиши в поле редактора.
4. Подтверждение уровня привязки ПКМ→Esc (в репозитории привязка
   отсутствует — предположительно уровень устройства) и отсутствия
   иных клавиш-синонимов.

## 10. Критерии приёмки

1. ПКМ и одиночный Esc в любом состоянии не выполняют действий.
2. Выход стрелкой за край: корректный изменённый блок сохранён,
   открыт соседний; некорректный — звук, рамка, сообщение, блок
   остаётся открытым.
3. Неизменённый блок при переходе не переформатируется и не
   записывается на диск.
4. Ctrl+V в редактировании вставляет текст без добавления символа
   «v»; в навигации вставляет блок(и).
5. Ctrl+Z отменяет последнее принятие, включая выполненное переходом.
6. Файл с синтаксической ошибкой доступен для исправления в
   построчном режиме; после исправления возвращается блочный режим.
7. Текущий режим отображается постоянно; ввод текста в навигации не
   изменяет файл.
8. Shift+Esc из редактирования восстанавливает исходный текст блока;
   из навигации закрывает редактор.
9. Ctrl+Y выполняет повтор отменённого действия; удаление блока
   выполняется только по Ctrl+Delete.
